## 1. 淘宝客 API

### 1.1 平台概况

淘宝客 (Taobao Ke) 是阿里巴巴旗下淘宝联盟的推广者平台，隶属于淘宝开放平台 (TOP, Taobao Open Platform)。通过 TOP API 实现商品搜索、详情获取、推广链接生成和佣金结算。

**官方入口:** https://open.taobao.com
**API 文档:** https://open.taobao.com/api.htm
**淘宝联盟后台:** https://pub.alimama.com

### 1.2 企业资质要求

| 条件         | 具体要求                 | 备注                       |
| ------------ | ------------------------ | -------------------------- |
| 营业执照     | 需要企业营业执照         | 个体工商户不行，必须是公司 |
| 注册资本     | >= 100 万元              | 实缴或认缴均可             |
| 公司成立时间 | >= 1 年                  | 以营业执照登记日期为准     |
| 应用审核     | 需提交应用说明和用途     | 审核周期 3-7 个工作日      |
| 高级权限     | 部分高佣金类目需额外申请 | 服装类目通常可直接通过     |

**申请流程:**

1. 注册淘宝开放平台账号 (使用企业支付宝)
2. 创建应用 (获取 AppKey + AppSecret)
3. 提交资质审核 (营业执照 + 应用说明)
4. 审核通过后获取 API 调用权限
5. 在淘宝联盟后台创建推广位 (获取 adzoneId)
6. 申请对应 API 权限包

**注意事项:**

- 个人开发者只能获取基础权限，无法使用淘宝客推广类 API
- 审核期间可使用沙箱环境测试，但沙箱数据与正式环境有差异
- 2025 年起淘宝联盟加强了对推广者质量的审核，新申请可能需要提供流量证明

3. 使用多个 AppKey 分流 (需多个企业主体, 不推荐)

### 1.5 签名机制

所有 API 请求使用 HMAC-SHA256 签名:

```
签名步骤:
1. 将所有业务参数按字母序排列
2. 拼接为 key=value 格式, 用 & 连接
3. 在头部拼接 AppSecret
4. 对整个字符串做 HMAC-SHA256 (使用 AppSecret 作为密钥)
5. 将结果转为大写十六进制字符串
6. 放入 sign 参数
```

**示例 (伪代码):**

```typescript
function generateSign(params: Record<string, string>, appSecret: string): string {
  const sorted = Object.keys(params).sort();
  const baseString = sorted.map((k) => `${k}${params[k]}`).join("");
  const hmac = crypto.createHmac("sha256", appSecret);
  hmac.update(baseString);
  return hmac.digest("hex").toUpperCase();
}
```

## 2. 京东联盟 API

### 2.1 平台概况

京东联盟 (JD Alliance / JD Union) 是京东旗下联盟营销平台。与淘宝客类似, 但数据结构和认证机制不同。

**官方入口:** https://union.jd.com
**API 文档:** https://union.jd.com/openplatform/api
**联盟后台:** https://union.jd.com

### 2.2 企业资质要求

| 条件         | 具体要求            | 与淘宝客差异             |
| ------------ | ------------------- | ------------------------ |
| 营业执照     | 需要企业营业执照    | 相同                     |
| 注册资本     | 无明确最低要求      | 比淘宝宽松               |
| 公司成立时间 | 无明确要求          | 比淘宝宽松               |
| 媒体资质     | 网站或 APP 需已上线 | 需提供下载链接或网站 URL |
| 备案要求     | 网站需有 ICP 备案   | 与淘宝相同               |

**申请流程:**

1. 注册京东联盟账号
2. 创建推广位 (siteId + positionId)
3. 创建应用获取 AppKey + AppSecretKey
4. 提交资质审核 (通常 1-3 个工作日, 快于淘宝)

### 3.2 XUNO 数据分类与敏感度判定

#### 3.2.1 GB/T 45574-2025 关键判定

**国家标准 GB/T 45574-2025 附录 A 明确规定:**

> 注 (e): 个人的体重、身高、血型、血压和肺活量等基本体质信息, 如与个人的疾病和医疗就诊无关, 则可认为不属于敏感个人信息范畴。

**据此, XUNO 收集的数据分类如下:**

| 数据项                         | 敏感度分类   | 法律依据                                 | 处理要求             |
| ------------------------------ | ------------ | ---------------------------------------- | -------------------- |
| 身高                           | **非敏感**   | GB/T 45574-2025 附录 A 注(e)             | 正常个人信息保护即可 |
| 体重                           | **非敏感**   | GB/T 45574-2025 附录 A 注(e)             | 正常个人信息保护即可 |
| 体型分类 (矩形/梨形/苹果形等)  | **非敏感**   | 衍生自身高体重, 不涉及疾病诊断           | 正常个人信息保护即可 |
| 年龄段 (18-25/25-35/35-45/45+) | **非敏感**   | 年龄段非精确年龄, 不构成身份识别         | 正常个人信息保护即可 |
| 三围数据 (胸围/腰围/臀围)      | **可能敏感** | 超出"基本体质"范畴, 泄露可能侵害人格尊严 | 建议按敏感信息处理   |
| 肩宽/臂长/腿长                 | **可能敏感** | 同上, 详细身体测量数据                   | 建议按敏感信息处理   |
| 用户照片 (含面部)              | **敏感**     | 属于生物识别信息 (面部特征)              | 必须按敏感信息处理   |
| 用户照片 (不含面部, 仅身体)    | **敏感**     | 身体照片可能泄露敏感体型信息             | 建议按敏感信息处理   |
| 体脂率 (计算值)                | **可能敏感** | 属于健康相关衍生数据                     | 建议按敏感信息处理   |
| 服装尺码 (S/M/L/XL)            | **非敏感**   | 不直接关联个人身体特征                   | 正常处理即可         |
| 场景偏好/风格表达              | **非敏感**   | 行为偏好数据                             | 正常处理即可         |
| 购买记录                       | **可能敏感** | 涉及消费能力 + 个人品味                  | 建议按敏感信息处理   |
| AI 对话记录                    | **可能敏感** | 可能包含身体描述/尺码信息                | 建议按敏感信息处理   |

### 3.3 单独同意机制技术实现

#### 3.3.1 法律要求

PIPL 第 29 条 + GB/T 45574-2025 第 5.4.2 条:

> 处理敏感个人信息应当取得个人的**单独同意**。单独同意不应与一般条款捆绑。

**具体要求 (来自国标 5.4.2):**

1. 单独同意可通过以下方式实现:
   - **独立页面展示** -- 在通用隐私政策之外, 单独弹窗/页面
   - **分目的勾选** -- 每个处理目的独立勾选框, 不可一键全选
   - **肯定性操作** -- 每种数据类型需用户主动点击确认
2. 禁止以下行为:
   - 将敏感信息同意与通用条款捆绑为一揽子授权
   - 拒绝同意后拒绝提供非敏感信息相关的基础服务
   - 暗示"同意" (如预勾选、默认同意)

#### 3.3.2 XUNO 实现方案

```
Onboarding 流程中的单独同意节点:

Step 1: 场景选择
  -> 无敏感数据, 无需单独同意
  -> 通用隐私政策告知即可

Step 2: 快速画像 (身高/体重/尺码)
  -> 身高/体重: 非敏感, 通用告知
  -> [如果收集三围]: 弹出单独同意窗口
     "我们想了解您的详细体型数据以提供更精准的尺码匹配建议。"
     [同意收集] [暂不提供]
     注意: 拒绝后仍可使用基础推荐服务

Step 3: 风格表达 (图片选择)
  -> 无敏感数据, 无需单独同意

Step 4: 照片上传 (可选)
  -> 弹出单独同意窗口 (必须, 因为照片含面部):
     目的1: "用于虚拟试衣展示" [独立勾选框]
     目的2: "用于AI体型分析" [独立勾选框]
     目的3: "用于个性化推荐优化" [独立勾选框]
     [确认授权]
     注意: 每个目的必须独立勾选, 不可一键全选
```

- 软件说明书的截图应与实际提交的 App 截图一致
- 建议在 App 开发完成后立即申请, 不必等到最终版本
- 一个软著只能对应一个 App, XUNO 只需申请一个

### 5.2 XUNO 成本模型 (1000 DAU)

#### 5.2.1 假设条件

| 参数                    | 值                         | 依据                                          |
| ----------------------- | -------------------------- | --------------------------------------------- |
| DAU                     | 1,000                      | 目标用户量                                    |
| 每用户每日推荐请求      | 3 次                       | Today Tab 打开 + Discover 刷新 + Stylist 咨询 |
| 每次推荐需 LLM 解释     | 1 次                       | L5 得分后 top-3 需要自然语言解释              |
| 每次解释消耗 tokens     | 约 500 (输入) + 200 (输出) | 推荐 context + 生成解释                       |
| 每用户每日 Stylist 对话 | 2 轮                       | 平均 2 次对话轮次                             |
| 每轮对话消耗 tokens     | 约 800 (输入) + 400 (输出) | 上下文 + 回复                                 |
| 试衣请求                | 0.5 次/用户/天             | 50% 的用户使用试衣                            |
| 每月天数                | 30                         |                                               |

#### 5.2.2 方案 A: GLM-4-Flash 全免费 (推荐初期方案)

| 用途          | 每日调用量   | 每日 token 消耗 | 月费用   |
| ------------- | ------------ | --------------- | -------- |
| 推荐解释生成  | 3,000 次     | 2.1M tokens     | 0 元     |
| Stylist 对话  | 2,000 轮     | 2.4M tokens     | 0 元     |
| 试衣描述/分析 | 500 次       | 0.3M tokens     | 0 元     |
| **总计**      | **5,500 次** | **4.8M tokens** | **0 元** |

**结论:** 如果 GLM-4-Flash 质量满足需求, 1000 DAU 下的 LLM 成本为 **0 元/月**。

#### 5.2.3 方案 B: 混合模型 (推荐生产方案)

| 用途           | 模型         | 每日调用量   | 每日 token 消耗 | 月费用        |
| -------------- | ------------ | ------------ | --------------- | ------------- |
| 推荐解释生成   | GLM-4-Flash  | 3,000 次     | 2.1M tokens     | 0 元          |
| Stylist 对话   | GLM-4-Air    | 2,000 轮     | 2.4M tokens     | ~46 元        |
| 试衣描述/分析  | GLM-4V-Flash | 500 次       | 0.3M tokens     | 0 元          |
| 场景卡 AI 摘要 | GLM-4-Flash  | 1,000 次     | 0.5M tokens     | 0 元          |
| **总计**       |              | **6,500 次** | **5.3M tokens** | **~46 元/月** |

**计算过程:**

- Stylist 对话: 2,000 轮 \* (800 输入 + 400 输出) = 2.4M tokens
  - 输入成本: 2.4M _ 60% _ 0.5/M = 0.72 元/天
  - 输出成本: 2.4M _ 40% _ 1.0/M = 0.96 元/天
  - 每日小计: 1.68 元
  - 月费用: 1.68 \* 30 = ~50 元
