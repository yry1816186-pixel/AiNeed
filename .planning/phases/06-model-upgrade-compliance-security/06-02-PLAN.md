# Plan 06-02: SASRec Pipeline + 6-Layer Funnel + Mixed Explanation

<objective>
Enable SASRec Python service as primary recommendation path, implement complete 6-layer funnel (L1-L6) with proper breakdown tracking, and generate mixed explanations (rule evidence + LLM polish).
</objective>

<must_haves>

- SASRec NestJS service calls Python /predict endpoint (no fake embeddings)
- 6-layer funnel fully implemented: L1 compliance, L2 scene, L3 size, L4 budget, L5 style scoring, L6 wardrobe complementary
- All breakdown fields (afterStyleFilter, afterWardrobeFilter) populated with real counts
- Mixed explanation: rule engine evidence + LLM polish
  </must_haves>

<task id="06-02-02">
<read_first>
- apps/backend/src/domains/platform/recommendations/orchestrator/recommendation.orchestrator.ts
- apps/backend/src/domains/platform/recommendations/types/recommendation.types.ts
</read_first>
<objective>Implement complete 6-layer funnel with L1 compliance filter and proper L5/L6 layers</objective>
<action>
1. In `recommendation.orchestrator.ts`:
   - Add L1 compliance filter method `filterByCompliance(items: ClothingItem[], userId: string): Promise<ClothingItem[]>` that:
     a. Checks UserConsent for `body_metrics` consent — if not granted, remove items requiring body metrics
     b. Checks UserConsent for `photos` consent — if not granted, remove items requiring photo analysis
     c. Returns filtered items
   - Add L5 style scoring method `filterByStyle(items: ClothingItem[], profile: UserProfile): ClothingItem[]` that:
     a. Score each item's style match using `styleExpression` from profile
     b. Remove items with style score below threshold (0.3)
     c. Return filtered items
   - Add L6 wardrobe complementary method `filterByWardrobe(items: ClothingItem[], wardrobeItems: ClothingItem[]): ClothingItem[]` that:
     a. Check each candidate against existing wardrobe items
     b. Remove items that are too similar (cosine similarity > 0.9) to existing wardrobe
     c. Prioritize complementary items (different category from recent purchases)
     d. Return filtered items

2. Update `recommend()` method to call all 6 layers in sequence:

   ```
   L1: filterByCompliance → count = afterCompliance
   L2: filterByScene → count = afterSceneFilter
   L3: filterBySize → count = afterSizeFilter
   L4: filterByBudget → count = afterBudgetFilter
   L5: filterByStyle → count = afterStyleFilter
   L6: filterByWardrobe → count = afterWardrobeFilter
   ```

3. Update `toRecommendationOutput()` to populate all breakdown fields:
   - Change `afterStyleFilter: 0` to `afterStyleFilter: styleFilteredCount`
   - Change `afterWardrobeFilter: 0` to `afterWardrobeFilter: wardrobeFilteredCount`
   - Add `totalCandidates: initialCount` (total before any filtering)
     </action>
     <acceptance_criteria>

- `recommendation.orchestrator.ts` contains `filterByCompliance` method (grep: `filterByCompliance`)
- `recommendation.orchestrator.ts` contains `filterByStyle` method (grep: `filterByStyle`)
- `recommendation.orchestrator.ts` contains `filterByWardrobe` method (grep: `filterByWardrobe`)
- `recommend()` method calls all 6 filter layers in sequence (grep: `filterByCompliance.*filterByScene.*filterBySize.*filterByBudget.*filterByStyle.*filterByWardrobe` or visual inspection of method)
- `toRecommendationOutput` does NOT contain `afterStyleFilter: 0` (grep returns empty)
- `toRecommendationOutput` does NOT contain `afterWardrobeFilter: 0` (grep returns empty)
- Breakdown fields populated with actual counts from filter results
  </acceptance_criteria>
  </task>
