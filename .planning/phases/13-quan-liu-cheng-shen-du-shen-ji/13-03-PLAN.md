**Step 1: Create `scripts/audit/wcag-audit.ts`**

The script performs static analysis on all `.tsx` files in `apps/mobile/src/` for WCAG 2.1 AA compliance:

**Audit checks:**

1. **Missing `accessibilityLabel`** — Scan for:

   - `<TouchableOpacity` without `accessibilityLabel` prop within the same JSX element
   - `<Pressable` without `accessibilityLabel`
   - `<Button` without `accessibilityLabel`
   - `<Image` without `accessibilityLabel` (decorative images can use `accessibilityLabel=""` or `accessible={false}`)
   - `<TextInput` without `accessibilityLabel`

2. **Touch targets < 44px** — Scan for:

   - `TouchableOpacity` or `Pressable` with explicit `width` or `height` style < 44
   - Icon buttons (Phosphor icons wrapped in touchable) without minimum touch target padding
   - Check for `hitSlop` as a mitigation (if hitSlop extends effective target to ≥ 44, it's OK)

3. **Color contrast violations** — Calculate contrast ratios for:

   - All text color + background color combinations from design tokens
   - `DesignTokens.colors.text.primary` (#1A1A18) on `backgrounds.primary` (#FFFFFF) → calculate
   - `DesignTokens.colors.text.secondary` (#52524D) on `backgrounds.primary` (#FFFFFF) → calculate
   - `DesignTokens.colors.text.tertiary` (#73736D) on `backgrounds.primary` (#FFFFFF) → calculate
   - `DesignTokens.colors.brand.terracotta` (#C67B5C) on `backgrounds.primary` (#FFFFFF) → calculate
   - `DesignTokens.colors.text.brand` (#9A5B3E) on `backgrounds.primary` (#FFFFFF) → calculate
   - Dark mode combinations: `#F5F2ED` on `#161412`, `#B8B0A8` on `#161412`
   - Use the WCAG 2.0 contrast formula: `(L1 + 0.05) / (L2 + 0.05)` where L is relative luminance
   - Flag any ratio below 4.5:1 for normal text or 3:1 for large text

4. **Missing `accessibilityRole`** — Scan for:

   - Touchable elements acting as buttons without `accessibilityRole="button"`
   - Touchable elements acting as links without `accessibilityRole="link"`
   - List items without `accessibilityRole="menuitem"` or similar

5. **Focus management** — Scan for:
   - Modal/BottomSheet components without focus trap
   - Screen transitions without focus management

For each finding, output structured data:

```typescript
{ file: string, line: number, element: string, issue: string, wcagCriterion: string, severity: "violation" | "warning", suggestion: string }
```

**Step 1: Create `scripts/audit/performance-baseline.ts`**

This script uses Playwright to measure web-mode performance. For each main screen:

```typescript
import { chromium, type Page } from "playwright";
```

Metrics to capture for each screen:

1. **First Contentful Paint (FCP)** — `page.evaluate(() => performance.getEntriesByName('first-contentful-paint')[0].startTime)`
2. **Time to Interactive (TTI)** — Approximate by measuring time from navigation to `page.waitForSelector` of main content + network idle
3. **Largest Contentful Paint (LCP)** — `page.evaluate(() => performance.getEntriesByName('largest-contentful-paint')[0].startTime)`
4. **List render time** — For list screens (Discover, Wardrobe), measure time from navigation to first N items rendered
5. **Image load waterfall** — Capture network requests for image assets, calculate total image load time
6. **JavaScript bundle size** — Measure from network requests
7. **Memory usage** — `page.metrics()` for JS heap size

For each screen in the screen registry (from Plan 01):

- Navigate to the screen
- Wait for main content to render
- Capture all metrics
- Take a performance trace if possible

Output format: JSON with per-screen metrics.
