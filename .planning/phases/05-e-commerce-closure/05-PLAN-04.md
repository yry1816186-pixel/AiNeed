# Plan 05-04: Merchant, AI Size & Category Backend

<objective>
Implement merchant review flow, AI size recommendation, subcategory service, and search enhancement with multi-dimension filtering. These complete the remaining backend requirements for the e-commerce closure.
</objective>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-02 | AI size recommendation data leak — body measurements exposed | medium | Size recommendation endpoint requires JwtAuthGuard, only returns recommended size not raw body data |
| T-05-08 | Unverified merchant creates products | high | MerchantService.createProduct() checks merchant.verified=true before allowing product creation |
| T-05-09 | Merchant application fraud — fake business license | medium | Auto-validate business license format, require manual review for approval |
</threat_model>

   - After product creation, call StockNotificationService.checkAndNotify() if the item was previously out of stock

3. **Merchant order management**:
   - Add `getMerchantOrders(merchantId: string, status?: string, page: number, limit: number)` method: return orders containing items from this merchant's brand
   - Add `shipOrder(merchantId: string, orderId: string, trackingNumber: string, carrier: string)` method:
     - Verify order contains items from this merchant
     - Set order status='shipped', trackingNumber, carrier, shippedAt=now()
     - Emit ORDER_SHIPPED event

4. **Merchant inventory management**:
   - Add `updateStock(merchantId: string, itemId: string, stock: number)` method:

     - Update ClothingItem.stock
     - If stock was 0 and now > 0: call StockNotificationService.checkAndNotify()
     - Call StockNotificationService.checkLowStock()

<action>
Implement SizeRecommendationService with full business logic:

1. **`recommend(userId: string, itemId: string)`**:
   - Get user body data via getBodyData()
   - Get item details including brand and available sizes
   - If no body data: return { hasRecommendation: false, message: "请先完善体型数据" }
   - Match body measurements against size chart via matchSizeChart()
   - Consider user's purchase history: check previous orders for same brand, find most common size
   - Return: { hasRecommendation: true, recommendedSize: string, confidence: number (0-100), reasons: string[] }
   - reasons format: ["根据您的{体型特征}，推荐{尺码}", "您之前购买该品牌选择了{尺码}"]

2. **`getBodyData(userId: string)`**:
   - Query UserProfile for height, weight, bust, waist, hips measurements
   - If measurements exist, return them
   - If not, return null (caller should handle by not showing AI recommendation)

3. **`matchSizeChart(bodyData: BodyData, sizeChart: SizeChart)`**:
   - Size chart format: { sizes: [{ label: 'S', measurements: { bust: [80, 84], waist: [60, 64], hips: [86, 90] } }, ...] }
   - For each size, calculate match score:
     - For each measurement (bust, waist, hips), check if body value falls within size range
     - Score = number of measurements within range / total measurements
   - If no brand size chart available, use default Chinese standard size chart:
     - S: bust 80-84, waist 60-64, hips 86-90
     - M: bust 84-88, waist 64-68, hips 90-94
     - L: bust 88-92, waist 68-72, hips 94-98
     - XL: bust 92-96, waist 72-76, hips 98-102
     - XXL: bust 96-100, waist 76-80, hips 102-106
   - Return best matching size with confidence score

4. **`getDefaultSizeChart()`**: Return the default Chinese standard size chart above

Implement SizeRecommendationController:

- `GET /api/v1/size-recommendation/:itemId` — get AI size recommendation (JwtAuthGuard)
  - Returns { hasRecommendation, recommendedSize?, confidence?, reasons? }
    </action>
