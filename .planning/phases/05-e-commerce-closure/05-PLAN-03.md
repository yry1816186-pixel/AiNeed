# Plan 05-03: Order, Payment & Refund Backend

<objective>
Implement RefundRequestService with full refund flow. Enhance OrderService with refund integration, confirm receipt, auto-confirm cron, and soft delete. Enhance PaymentService with frontend-facing payment endpoints. Create LogisticsService for shipping tracking API integration.
</objective>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-03 | Payment callback forgery | high | Verify callback signature using Alipay/WeChat public keys, validate amount matches order |
| T-05-04 | Payment idempotency bypass | high | Redis distributed lock + Lua script atomic release (already implemented in PaymentService) |
| T-05-07 | Refund amount exceeds payment | high | RefundRequest.amount validated against PaymentRecord.amount in $transaction, sum of all refunds for order cannot exceed paid amount |
| T-05-11 | Logistics API key exposure | medium | Store API key in environment variable, never log raw API responses |
</threat_model>

<action>
Implement RefundRequestService with full business logic:

1. **`create(userId: string, data: CreateRefundDto)`**:
   - Verify order belongs to userId and status is 'paid' or 'completed'
   - Verify order was completed within 7 days (for COMM-12: 7-day refund window)
   - Calculate total refund amount from OrderItemRefund entries, validate sum <= PaymentRecord.amount for the order
   - For type=return_refund, require images[] to be non-empty
   - Create RefundRequest with status=pending
   - Create OrderItemRefund entries for each item being refunded
   - Return RefundRequest with itemRefunds

2. **`approve(id: string, reviewerId: string)`**:
   - Verify RefundRequest status is 'pending'
   - Set status=approved, reviewedAt=now()
   - If type=refund_only: call processRefund() immediately
   - If type=return_refund: wait for user to submit tracking number

3. **`reject(id: string, reviewerId: string, reason: string)`**:
   - Verify RefundRequest status is 'pending'
   - Set status=rejected, rejectReason=reason, reviewedAt=now()

4. **`confirmReturn(id: string, userId: string, trackingNumber: string)`**:
   - Verify RefundRequest belongs to userId and status is 'approved' and type is 'return_refund'
   - Set trackingNumber on the RefundRequest
   - Merchant will later confirm receipt, triggering processRefund()

5. **`confirmReturnReceipt(id: string, merchantId: string)`**:
   - Verify RefundRequest status is 'approved' and has trackingNumber
   - Call processRefund()

6. **`processRefund(id: string)`**:
   - Set status=processing
   - Call PaymentService.refund() with the refund amount
   - On success: set status=completed, completedAt=now()
   - On failure: log error, keep status=processing for manual review
   - Emit REFUND_COMPLETED event via EventEmitter2

7. **`getByOrder(orderId: string)`**: Return all RefundRequests for orderId with itemRefunds

8. **`getByUser(userId: string)`**: Return all RefundRequests for userId, paginated

9. **`getPendingReviews()`**: Return all RefundRequests with status=pending (for merchant/admin)

Implement RefundRequestController with all routes, adding JwtAuthGuard and proper Swagger decorators.

DTOs:

- CreateRefundDto: { orderId: string, type: RefundType, reason: string, images?: string[], items: { orderItemId: string, quantity: number }[] }
- RejectRefundDto: { reason: string }
- ReturnRefundDto: { trackingNumber: string }

<action>
Enhance OrderService with the following additions:

1. **Confirm receipt**: Add `confirmReceipt(userId: string, orderId: string)` method:
   - Verify order belongs to userId and status is 'shipped'
   - Set status='completed', completedAt=now()
   - Emit ORDER_COMPLETED event

2. **Auto-confirm cron**: Add `@Cron('0 0 * * *')` (daily at midnight) method `autoConfirmOrders()`:
   - Find all orders with status='shipped' and shippedAt < now() - 15 days
   - For each, set status='completed', completedAt=now()
   - Log count of auto-confirmed orders

3. **Soft delete**: Add `softDelete(userId: string, orderId: string)` method:
   - Verify order belongs to userId and status is 'completed' or 'cancelled'
   - Set isDeleted=true, deletedAt=now()
   - Return void

4. **Refund integration**: In the `cancel()` method, if order is already paid:
   - Create a RefundRequest with type=refund_only instead of directly calling PaymentService.refund()
   - The refund flow goes through RefundRequestService for proper tracking

5. **Order search**: Add `searchOrders(userId: string, keyword: string, status?: string, page: number, limit: number)` method:
   - Search by orderNo or itemName (from OrderItem)
   - Filter by status if provided
   - Paginated results

6. **Get orders by status tabs**: Add `getOrdersByTab(userId: string, tab: 'pending' | 'paid' | 'shipped' | 'completed' | 'refund', page: number, limit: number)`:
   - Map tab to status filter: pending→pending, paid→paid+processing, shipped→shipped, completed→completed, refund→refund_requested
   - Return paginated orders with items

Enhance OrderController:

- Add `PUT /api/v1/orders/:id/confirm` — confirm receipt
- Add `DELETE /api/v1/orders/:id` — soft delete order
- Add `GET /api/v1/orders/tab/:tab` — get orders by tab
- Add `GET /api/v1/orders/search` — search orders
  </action>
