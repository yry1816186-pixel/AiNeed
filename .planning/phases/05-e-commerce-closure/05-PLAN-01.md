<objective>
Add all new Prisma models (Coupon, UserCoupon, StockNotification, RefundRequest, OrderItemRefund, Subcategory) and create backend service stubs for new modules. Run [BLOCKING] schema push to sync database.

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-01 | Coupon brute-force — attacker guesses coupon codes | medium | Coupon codes are 8-char random, rate-limit coupon validation endpoint |
| T-05-05 | Coupon abuse — user uses coupon beyond limit | high | Enforce usageLimit + perUserLimit in CouponService.validate(), atomic increment with $transaction |
| T-05-06 | Refund amount exceeds payment | high | RefundRequest.amount validated against OrderItem.price \* quantity, capped at PaymentRecord.amount |
</threat_model>

**New models:**

```prisma
model Coupon {
  id                    String              @id @default(uuid())
  code                  String              @unique
  type                  CouponType
  value                 Decimal             @db.Decimal(10, 2)
  minOrderAmount        Decimal?            @db.Decimal(10, 2) @default(0)
  maxDiscount           Decimal?            @db.Decimal(10, 2)
  validFrom             DateTime
  validUntil            DateTime
  usageLimit            Int?
  usedCount             Int                 @default(0)
  perUserLimit          Int                 @default(1)
  applicableCategories  String[]
  applicableBrandIds    String[]
  isActive              Boolean             @default(true)
  createdAt             DateTime            @default(now())
  updatedAt             DateTime            @updatedAt
  userCoupons           UserCoupon[]

  @@index([code])
  @@index([isActive, validFrom, validUntil])
  @@map("coupons")
}

model UserCoupon {
  id          String       @id @default(uuid())
  userId      String
  couponId    String
  status      CouponStatus @default(available)
  usedAt      DateTime?
  orderId     String?
  createdAt   DateTime     @default(now())
  updatedAt   DateTime     @updatedAt
  user        User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  coupon      Coupon       @relation(fields: [couponId], references: [id], onDelete: Cascade)

  @@unique([userId, couponId])
  @@index([userId, status])
  @@map("user_coupons")
}

model StockNotification {
  id          String                   @id @default(uuid())
  userId      String
  itemId      String
  color       String?
  size        String?
  status      StockNotificationStatus  @default(pending)
  notifiedAt  DateTime?
  createdAt   DateTime                 @default(now())
  updatedAt   DateTime                 @updatedAt
  user        User                     @relation(fields: [userId], references: [id], onDelete: Cascade)
  item        ClothingItem             @relation(fields: [itemId], references: [id], onDelete: Cascade)

  @@unique([userId, itemId, color, size])
  @@index([itemId, status])
  @@map("stock_notifications")
}

model RefundRequest {
  id              String              @id @default(uuid())
  orderId         String
  userId          String
  type            RefundType
  reason          String
  status          RefundRequestStatus @default(pending)
  images          String[]
  amount          Decimal             @db.Decimal(10, 2)
  rejectReason    String?
  trackingNumber  String?
  reviewedAt      DateTime?
  completedAt     DateTime?
  createdAt       DateTime            @default(now())
  updatedAt       DateTime            @updatedAt
  order           Order               @relation(fields: [orderId], references: [id], onDelete: Restrict)
  user            User                @relation(fields: [userId], references: [id], onDelete: Cascade)
  itemRefunds     OrderItemRefund[]

  @@index([orderId])
  @@index([userId, status])
  @@index([status])
  @@map("refund_requests")
}

model OrderItemRefund {
  id               String        @id @default(uuid())
  orderItemId      String
  refundRequestId  String
  quantity         Int
  amount           Decimal       @db.Decimal(10, 2)
  createdAt        DateTime      @default(now())
  refundRequest    RefundRequest @relation(fields: [refundRequestId], references: [id], onDelete: Cascade)

  @@index([refundRequestId])
  @@map("order_item_refunds")
}

model Subcategory {
  id          String   @id @default(uuid())
  parentId    String?
  name        String
  slug        String
  level       Int      @default(1)
  sortOrder   Int      @default(0)
  icon        String?
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  parent      Subcategory?  @relation("SubcategoryTree", fields: [parentId], references: [id], onDelete: SetNull)
  children    Subcategory[] @relation("SubcategoryTree")

  @@unique([parentId, slug])
  @@index([parentId, sortOrder])
  @@index([level, isActive])
  @@map("subcategories")
}
```

Add relation fields to existing models:

- `ClothingItem` model: add `stockNotifications StockNotification[]`

Also add `Subcategory` relation to `ClothingItem` if a `subcategoryId` field makes sense (add `subcategoryId String?` and `subcategory Subcategory? @relation(fields: [subcategoryId], references: [id])`).

<action>
Create the following NestJS modules with service + controller stubs. Follow the existing pattern from CartModule (Injectable service, Controller with Swagger decorators, Module registration).

**1. CouponModule** (`apps/backend/src/modules/coupon/`):

- `coupon.module.ts`: imports PrismaModule, provides CouponService, registers CouponController
- `coupon.service.ts`: Injectable class with stub methods:
  - `create(data: CreateCouponDto)` — creates a coupon
  - `findByCode(code: string)` — finds active coupon by code
  - `validate(code: string, userId: string, orderAmount: number)` — validates coupon eligibility (expiry, usage limit, per-user limit, min order amount, applicable categories/brands)
  - `apply(code: string, userId: string, orderId: string)` — applies coupon: creates UserCoupon, increments usedCount in $transaction
  - `getUserCoupons(userId: string)` — returns user's available/used/expired coupons
  - `deactivate(id: string)` — sets isActive = false
- `coupon.controller.ts`: Controller with routes:
  - `POST /api/v1/coupons/validate` — validate coupon code
  - `POST /api/v1/coupons/apply` — apply coupon to order
  - `GET /api/v1/coupons/my` — get user's coupons
  - `POST /api/v1/coupons` — admin: create coupon (protected by AdminGuard)
- `dto/index.ts`: CreateCouponDto, ValidateCouponDto, ApplyCouponDto with class-validator decorators

**2. StockNotificationModule** (`apps/backend/src/modules/stock-notification/`):

- `stock-notification.module.ts`: imports PrismaModule, provides StockNotificationService
- `stock-notification.service.ts`: Injectable class with stub methods:
  - `subscribe(userId: string, itemId: string, color?: string, size?: string)` — create StockNotification with status=pending (unique constraint on userId+itemId+color+size)
  - `unsubscribe(userId: string, itemId: string, color?: string, size?: string)` — set status=cancelled
  - `checkAndNotify(itemId: string)` — check if item stock > 0 for pending notifications, update status=notified, emit event
  - `getUserNotifications(userId: string)` — return user's notifications
- `stock-notification.controller.ts`: Controller with routes:
  - `POST /api/v1/stock-notifications/subscribe` — subscribe to stock notification
  - `DELETE /api/v1/stock-notifications/:id` — cancel notification
  - `GET /api/v1/stock-notifications/my` — get user's notifications

**3. RefundRequestModule** (`apps/backend/src/modules/refund-request/`):

- `refund-request.module.ts`: imports PrismaModule, provides RefundRequestService
- `refund-request.service.ts`: Injectable class with stub methods:
  - `create(userId: string, data: CreateRefundDto)` — create RefundRequest with status=pending, validate amount <= order paid amount
  - `approve(id: string)` — set status=approved (merchant action)
  - `reject(id: string, reason: string)` — set status=rejected (merchant action)
  - `processRefund(id: string)` — call PaymentService.refund(), set status=processing then completed
  - `confirmReturn(id: string, trackingNumber: string)` — user provides return tracking number
  - `getByOrder(orderId: string)` — get refund requests for an order
  - `getByUser(userId: string)` — get user's refund requests
- `refund-request.controller.ts`: Controller with routes:
  - `POST /api/v1/refunds` — create refund request
  - `PUT /api/v1/refunds/:id/approve` — approve (merchant)
  - `PUT /api/v1/refunds/:id/reject` — reject (merchant)
  - `PUT /api/v1/refunds/:id/return` — submit return tracking (user)
  - `GET /api/v1/refunds/order/:orderId` — get refunds for order
  - `GET /api/v1/refunds/my` — get user's refunds
- `dto/index.ts`: CreateRefundDto, ApproveRefundDto, RejectRefundDto, ReturnRefundDto

**4. SubcategoryModule** (`apps/backend/src/modules/subcategory/`):

- `subcategory.module.ts`: imports PrismaModule, provides SubcategoryService
- `subcategory.service.ts`: Injectable class with stub methods:
  - `create(data: CreateSubcategoryDto)` — create subcategory
  - `getTree()` — return full category tree (level 1 → level 2 → level 3)
  - `getByParent(parentId: string)` — return children of a parent
  - `getBySlug(slug: string)` — find by slug
  - `update(id: string, data: UpdateSubcategoryDto)` — update subcategory
  - `delete(id: string)` — soft delete (set isActive=false)
- `subcategory.controller.ts`: Controller with routes:
  - `GET /api/v1/subcategories/tree` — get full tree
  - `GET /api/v1/subcategories/parent/:parentId` — get children
  - `POST /api/v1/subcategories` — admin: create
  - `PUT /api/v1/subcategories/:id` — admin: update
  - `DELETE /api/v1/subcategories/:id` — admin: delete

**5. SizeRecommendationModule** (`apps/backend/src/modules/size-recommendation/`):

- `size-recommendation.module.ts`: imports PrismaModule, provides SizeRecommendationService
- `size-recommendation.service.ts`: Injectable class with stub methods:
  - `recommend(userId: string, itemId: string)` — recommend size based on user body data + brand size chart; return { recommendedSize, confidence, reasons[] }
  - `getBodyData(userId: string)` — fetch user body measurements from UserProfile
  - `matchSizeChart(bodyData, sizeChart)` — match body measurements against brand size chart
- `size-recommendation.controller.ts`: Controller with routes:
  - `GET /api/v1/size-recommendation/:itemId` — get AI size recommendation for item

Register all 5 modules in `apps/backend/src/app.module.ts` imports array.
