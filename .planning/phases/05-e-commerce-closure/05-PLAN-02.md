# Plan 05-02: Promotion, Inventory & Cart Backend

<objective>
Implement CouponService and StockNotificationService with full business logic. Enhance CartService with coupon discount calculation, stock validation, and expired item cleanup. Enhance ClothingService with stock display, sales sort, and related recommendations.
</objective>

<threat_model>
| ID | Threat | Severity | Mitigation |
|----|--------|----------|------------|
| T-05-05 | Coupon abuse — user exceeds per-user limit | high | validate() checks UserCoupon count for userId+couponId, apply() uses $transaction for atomic increment |

<action>
Implement CouponService with full business logic:

1. **`create(data: CreateCouponDto)`**: Create coupon with code auto-generated if not provided. Code format: prefix (FIRST/PROMO) + 8 random alphanumeric chars. Validate validFrom < validUntil. If type=percentage, value must be <= 100.

2. **`findByCode(code: string)`**: Find coupon where `code = code AND isActive = true AND validFrom <= now() AND validUntil >= now()`. Return null if not found.

3. **`validate(code: string, userId: string, orderAmount: number, categoryIds?: string[], brandId?: string)`**:
   - Find coupon by code, throw BadRequestException if not found/expired/inactive
   - Check usageLimit: if usedCount >= usageLimit, throw "优惠券已领完"
   - Check perUserLimit: count UserCoupon where userId+couponId, if count >= perUserLimit, throw "您已达到领取上限"
   - Check minOrderAmount: if orderAmount < minOrderAmount, throw "未达到最低消费金额"
   - Check applicableCategories: if coupon has applicableCategories and none match, throw "该商品不适用此优惠券"
   - Check applicableBrandIds: if coupon has applicableBrandIds and none match, throw "该品牌不适用此优惠券"
   - Calculate discount: if type=percentage, discount = orderAmount \* value / 100, capped at maxDiscount; if type=fixed, discount = value; if type=shipping, discount = shipping fee amount
   - Return { coupon, discount, finalAmount: orderAmount - discount }

4. **`apply(code: string, userId: string, orderId: string)`**:
   - Use `$transaction` for atomicity:
     - Validate coupon (reuse validate logic)
     - Create UserCoupon with status=used, usedAt=now, orderId
     - Increment Coupon.usedCount by 1
   - Return UserCoupon

5. **`getUserCoupons(userId: string)`**: Return all UserCoupon for userId, include Coupon relation. Group by status.

6. **`checkAndApplyFirstOrder(userId: string, orderId: string, orderAmount: number)`**: Check if user has any completed orders. If not, find active coupon with code starting with "FIRST", auto-apply it.

7. **`deactivate(id: string)`**: Set isActive = false.

Implement CouponController with all routes from Plan 01, adding proper Swagger decorators, JwtAuthGuard, and request validation.

DTOs:

- CreateCouponDto: { code?: string, type: CouponType, value: number, minOrderAmount?: number, maxDiscount?: number, validFrom: Date, validUntil: Date, usageLimit?: number, perUserLimit?: number, applicableCategories?: string[], applicableBrandIds?: string[] }
- ValidateCouponDto: { code: string, orderAmount: number, categoryIds?: string[], brandId?: string }
- ApplyCouponDto: { code: string, orderId: string }

<action>
Implement StockNotificationService with full business logic:

1. **`subscribe(userId: string, itemId: string, color?: string, size?: string)`**:
   - Check if ClothingItem exists and stock <= 0 for the given color/size
   - Create StockNotification with status=pending
   - Handle unique constraint violation (already subscribed) gracefully with upsert

2. **`unsubscribe(id: string, userId: string)`**:
   - Find notification by id, verify userId matches, set status=cancelled

3. **`checkAndNotify(itemId: string)`**:
   - Called after stock update (from MerchantService or OrderService)
   - Find all pending StockNotifications for itemId
   - For each, check if the specific color/size is now in stock
   - If in stock: update status=notified, notifiedAt=now(), emit STOCK_AVAILABLE event via EventEmitter2
   - Return count of notifications sent

4. **`getUserNotifications(userId: string)`**:
   - Return all notifications for userId, include ClothingItem relation
   - Order by createdAt desc

5. **`checkLowStock(itemId: string)`**:
   - Read ClothingItem.stock and lowStockThreshold
   - If stock <= lowStockThreshold, emit LOW_STOCK event via EventEmitter2
   - Return { isLowStock: boolean, stock: number, threshold: number }

Implement StockNotificationController with all routes, adding JwtAuthGuard.

Add EventEmitter2 integration: inject EventEmitter2 in StockNotificationService, emit `stock.available` and `stock.low` events.

7. **Inline SKU update**: Add `updateItemSku(userId: string, cartItemId: string, color?: string, size?: string)` method that updates the SKU selection. Check for duplicate (same itemId+color+size) and merge quantities if needed.
