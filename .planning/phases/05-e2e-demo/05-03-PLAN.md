# Plan 05-03: Demo Mode Isolation + Profile Switching

**Goal:** Ensure demo mode toggle cleanly separates demo data from real user data and supports rapid profile switching.

## Tasks

### Task 1: Implement Demo Mode Toggle in Developer Settings

<action>
1. Add a toggle switch in the developer settings screen (or create a simple dev settings panel accessed via long-press on app version in Me tab).

2. When toggled ON, set a Zustand state `demoMode: boolean` or AsyncStorage key `@demo_mode_enabled`.

3. When `demoMode === true`:

   - All API calls route through a demo interceptor that:
     - Returns pre-cached data for recommendation/look endpoints
     - Never sends real user data mutations
     - Displays "DEMO MODE" banner at top of screen (non-intrusive, semi-transparent)
   - Show Debug FAB (ProfileDebugPanel) on Stylist tab
   - Preload 10 seed profiles from `docs/PRESENTATION/seed-user-data-v2.json` to local state
   - Disable crash reporting to analytics services

4. When toggled OFF:

   - Resume normal API calls
   - Hide Debug FAB
   - Clear preloaded demo data
   - Re-enable analytics

5. persistence: Demo mode state MUST survive app restart (use AsyncStorage). Banner MUST NOT appear on screenshots (position: absolute with pointerEvents 'none').
   </action>
