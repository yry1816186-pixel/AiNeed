# Plan 05-04: Fallback Pipeline + Voice Reliability

**Goal:** Implement 4-tier fallback cascade (Live → Qwen → Cached → Video/PPT) and ensure voice input reliability for competition demo.

## Tasks

### Task 1: Implement GLM → Qwen Auto-Failover

<action>
Modify `apps/backend/src/domains/ai-core/services/`:

1. Create `ai-fallback.service.ts` with method `callWithFallback(prompt, options)`:

   - Try GLM-4-Flash first with 5s timeout (already configured in existing service)
   - On timeout or error (status >= 500 || network error), automatically retry with Qwen API using same prompt format
   - On Qwen success: log `[FALLBACK] GLM->Qwen for {operation}`, return result
   - On Qwen failure: throw `AiFallbackExhaustedException` with both error messages
   - Wrap in try-catch with structured error logging

2. Create `tts-fallback.service.ts`:

   - Primary: Edge-TTS (existing)
   - Fallback: return text-only response (no audio) with status `audio_unavailable`
   - Log fallback events with phrase key

3. Inject fallback services into existing `ai-stylist.service.ts` and voice handler.

4. Set timeout config in backend `.env`:
   - `AI_PRIMARY_TIMEOUT_MS=5000`
   - `AI_FALLBACK_TIMEOUT_MS=5000`
   - `TTS_TIMEOUT_MS=3000`
