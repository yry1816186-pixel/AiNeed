## 2. 执行阶段（每用户 30-45 分钟）

### 2.0 开场白（逐字稿，2 分钟）

> 欢迎参加寻裳 App 的用户体验测试！
>
> 今天请你来不是测试你，而是测试我们的 App。所以没有对错之分，你按照自己的想法用就好。
>
> 几个小请求：
>
> 1. **边用边说出你的想法** — 比如"我在找...""这个有点奇怪"之类的，你的实时感受对我们特别有价值。
> 2. **我不会帮你操作** — 如果你卡住了，我会让你多试试，不会直接告诉你怎么点。这是为了发现设计上的问题。
> 3. **全程录屏** — 只录 App 画面和你的语音，不会泄露隐私。
>
> 有问题随时问，不过有些问题我可能要等测试结束再回答。准备好了我们就开始吧！

### 2.1 任务 A：Onboarding 画像建立（目标 5 分钟内）

**引导脚本（逐字稿）**：

> "请打开 App，从注册开始，按照你真实的想法一步步操作下去。最后会生成一个你的穿搭画像。"

**计时起点**：用户点击 App 图标。
**计时终点**：用户看到画像生成结果页。

**观察要点**：

| 步骤 | 观察重点                               | 记录项                      |
| ---- | -------------------------------------- | --------------------------- |
| A1   | 首屏是否理解？是否知道该注册还是登录？ | 犹豫时间（秒）              |
| A2   | 表单填写是否顺畅？验证码是否收到？     | 错误操作次数                |
| A3   | Onboarding 每步是否理解目的？          | 每步停留时间                |
| A4   | 风格测试图片选择是否犹豫？             | 选择耗时、是否来回切换      |
| A5   | 场景选择是否找到自己需要的？           | 是否浏览多个场景            |
| A6   | 体型拍照引导是否清晰？是否愿意拍照？   | 拍照尝试次数、犹豫/抗拒情绪 |
| A7   | 画像结果是否认可？是否理解各维度含义？ | 用户自发言论、表情          |

**黄金标准**：

- 完成率 100%，耗时 ≤ 3 分钟（优秀）、3-5 分钟（良好）、> 5 分钟（需改进）
- 错误操作 0 次（优秀）

**关键纪律**：

- 用户卡住时只说"你想怎么做就怎么做"
- 连续卡住超过 2 分钟，提示"你可以试试其他方式"
- **不解释**任何功能

## 4. 分析阶段（Day 3）

### 4.1 SUS 评分计算

每位用户的 SUS 计算步骤：

```
1. 提取 10 题原始分数：S1, S2, S3, ..., S10（每题 1-5 分）

2. 奇数题转换（S1, S3, S5, S7, S9）：
   得分 = 原始分 - 1

3. 偶数题转换（S2, S4, S6, S8, S10）：
   得分 = 5 - 原始分

4. SUS 总分 = (所有转换后得分之和) × 2.5

5. 结果范围：0-100 分
```

**SUS 等级对照表**：

| 分数区间  | 等级 | 含义           | 行动             |
| --------- | ---- | -------------- | ---------------- |
| ≥ 80.3    | A    | 优秀，可推广   | 继续优化细节     |
| 68 - 80.3 | B    | 良好，基本可用 | 修复已知问题     |
| 51 - 68   | C    | 一般，需改进   | 重点优化核心流程 |
| < 51      | D    | 不可用，需重构 | 回到设计阶段     |

**计算示例**：

```
用户 #1 小林的原始分：
  S1=4, S2=2, S3=4, S4=1, S5=4, S6=2, S7=5, S8=1, S9=4, S10=1

奇数题转换：4-1=3, 4-1=3, 4-1=3, 5-1=4, 4-1=3 → 奇数和 = 16
偶数题转换：5-2=3, 5-1=4, 5-2=3, 5-1=4, 5-1=4 → 偶数和 = 18

SUS 总分 = (16 + 18) × 2.5 = 85.0 → 等级 A
```

### 4.2 NPS 计算

```
1. 统计每个用户的 NPS 打分（0-10）

2. 分类：
   0-6  = 贬损者（Detractor）
   7-8  = 中立者（Passive）
   9-10 = 推荐者（Promoter）

3. NPS = 推荐者占比 - 贬损者占比

示例（5 人中 3 推荐者、1 中立、1 贬损者）：
  NPS = (3/5 × 100) - (1/5 × 100) = 60 - 20 = 40
```

### 4.3 问题严重度分级标准

| 等级   | 定义                                | 修复时限 | 典型场景                         |
| ------ | ----------------------------------- | -------- | -------------------------------- |
| **P0** | 阻塞性 — 用户无法完成核心任务       | 立即修复 | 崩溃、登录失败、推荐数据不返回   |
| **P1** | 体验性 — 影响使用效率或满意度       | 1 周内   | 操作繁琐、理解困难、视觉混乱     |
| **P2** | 优化性 — 不影响核心流程但有提升空间 | 排期处理 | 文案不够好、动画不流畅、细节打磨 |

**判定方法**：

- **频率**：该问题在 5 人中出现几次？（≥ 3 次升级一级）
- **影响**：是否导致任务失败？（任务失败直接 P0）
- **情绪**：用户是否表达了明显不满？（不满 + 影响效率 → P1）

### 4.4 改进优先级矩阵

将所有发现的问题放入矩阵：

```
                    用户影响大
                        │
         P0（立即修）   │   P1（尽快修）
                        │
   ─────────────────────┼──────────────────────
                        │
         P2（排期修）   │   P2（可考虑）
                        │
                    用户影响小
           出现频率低            出现频率高
```

**决策规则**：

1. 频率高 + 影响大 → **P0**
2. 频率低 + 影响大 → **P1**
3. 频率高 + 影响小 → **P1**
4. 频率低 + 影响小 → **P2**

### 4.5 结果汇总到 results-template.md

按以下顺序填写：
