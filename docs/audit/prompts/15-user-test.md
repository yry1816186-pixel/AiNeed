# 轨道 15: 种子用户测试框架

你是 XUNO 项目的用户研究工程师。你要设计并执行一个 5 人种子用户测试，收集真实反馈。

## 为什么这很重要

审计发现项目最大的弱点是"没有真实数据"。评委问"推荐准确率多少"时，回答"还没测"等于"系统没完成"。5 个真实用户的反馈 > 10000 个"计划"。

## 任务 1: 测试脚本设计

文件: `docs/TESTING/test-script.md`

### 测试流程（每人 30-45 分钟）

```
阶段1: 任务执行（20分钟）
  任务A: "打开App，完成Onboarding，找到面试穿搭推荐"
  - 记录: 每一步耗时、点击次数、犹豫点、错误操作
  - 不要帮助用户，只观察

  任务B: "和伊伊对话，让她帮你搭一套约会穿搭"
  - 记录: 对话轮数、用户表达方式、伊伊回复质量

  任务C: "查看推荐方案的匹配度分析"
  - 记录: 用户是否理解雷达图、是否认可评分

阶段2: 半结构化访谈（15分钟）
  Q1: "整体感觉怎么样？1-10分打几分？"
  Q2: "最让你惊喜的是什么？"
  Q3: "最让你困惑的是什么？"
  Q4: "你觉得伊伊像什么？朋友？导购？工具？"
  Q5: "你会不会在真实面试前用这个？为什么？"
  Q6: "你觉得这个App值多少钱？你会付费吗？"
  Q7: "和淘宝/小红书的穿搭推荐比，哪个更好？"

阶段3: 系统可用性量表SUS（5分钟）
  10道标准SUS题目，每题5分
```

## 任务 2: 测试环境准备

### Mock 数据确保推荐质量

测试前确保以下场景的推荐是完美的：

1. 面试 + 互联网公司 + 简约利落 → 3 套黄金推荐
2. 约会 + 温柔优雅 → 3 套黄金推荐
3. 日常通勤 + 活力运动 → 3 套黄金推荐

使用轨道 10 准备的黄金推荐方案，硬编码到测试环境中。

### 录屏工具

- Android: `adb shell screenrecord /sdcard/test.mp4`
- 或用系统自带录屏
- 确保有声音录制（用户说话）
