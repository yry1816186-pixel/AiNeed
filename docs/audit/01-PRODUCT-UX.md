## 维度 1：伊伊 Agent 交互设计层级

**评分：5/10**
**标签：🟠 重要风险**

### 交互层级定位

根据 FINAL_PLAN.md 13.2 定义，Agent 交互有 5 个层级：

| 层级    | 描述                                       | 文档声称 | 代码实际                                                 |
| ------- | ------------------------------------------ | -------- | -------------------------------------------------------- |
| Level 1 | 被动响应：用户问 -> AI 答 -> 结束          | --       | AiStylistChat 当前实现就在这里                           |
| Level 2 | 主动追问：答后追问 -> 细化 -> 更好方案     | 最低标准 | 对话状态机(YIYI-01)尚未实现，快速回复按钮(YIYI-05)不存在 |
| Level 3 | 场景感知：感知天气/日历/位置 -> 主动开口   | 目标标准 | 天气 API 集成未完成，日历读取未规划(48h 内)              |
| Level 4 | 风格学习：记住偏好历史 -> 越用越准         | 壁垒标准 | 偏好记忆(YIYI-07)标注为 Pending                          |
| Level 5 | 风格进化追踪：理解风格变化 -> 预测未来偏好 | 终极标准 | 纯愿景，无任何规划                                       |

**代码证据**：

- RootNavigator.tsx 仍然是 5 Tab 导航（Home/Stylist/TryOn/Community/Profile），而非规划中的 4 Tab（Today/Discover/Stylist/Me）
- 不存在 TodayScreen 组件
- 不存在对话状态机实现
- 不存在快速回复按钮
- 不存在场景感知推送机制

**残酷的真相**：FINAL_PLAN 声称 XUNO 的核心体验是"主动找上门的 AI 穿搭搭子"，但当前代码里伊伊是一个被动等待用户输入的聊天框。从 Level 1.5 到 Level 3 的跳跃，不是 48 小时能完成的——这需要新的交互范式、新的导航架构、新的推送系统、新的状态管理。

**真正要做的**：

1. 48 小时内把伊伊从 Level 1 推到 Level 2（对话状态机 + 快速回复按钮 + 追问机制）—— 这是可行的
2. Level 3（场景感知主动开口）必须在 Sprint 后第 1-2 周完成，否则"体验壁垒"叙事不成立
3. Level 4（风格学习）才是真正的壁垒，但需要至少 100 个活跃用户的行为数据才有意义

## 维度 2：语音按钮用户接受度

**评分：4/10**
**标签：🟠 重要风险**

### 在中国穿搭场景的真实价值评估

文档将"首页语音按钮"列为"核心交互差异化"（决策 #15）。我对此持严重怀疑态度。

**支持语音的场景**：

- 双手拿着衣服在试衣间："伊伊，这件和我那条黑色裤子搭不搭？"
- 换季整理衣柜时："帮我看看哪些秋天还能穿"
- 做家务/化妆时语音提问

**不支持语音的场景（占 90%+的使用时间）**：

- 在地铁/公交上用手机 — 周围有人，语音输入极度尴尬
- 在办公室摸鱼看穿搭 — 更不想被听到
- 在宿舍/合租房 — 隐私顾虑
- 晚上躺床上刷手机 — 舍友/家人在旁边

**中国市场数据**：

- 2024 年 AIGC 应用渗透率仅 27.1%，语音助手使用率更低
- 车载语音是高接受度场景（封闭空间、手被占用），手机 App 不是
- 科大讯飞占 44.2%智能语音市场份额，但主要场景是教育、车载、会议转写
- 中国年轻用户在公共场合使用语音输入的接受度显著低于欧美

**竞品反例**：

- 小红书：无语音搜索，纯文字+图片，但用户日均使用时长超过 60 分钟
- 淘宝：有语音搜索但入口不显眼，绝大多数用户仍然打字
- 美图秀秀：没有语音交互，工具属性和 XUNO 最接近，用户照样用
- 抖音：语音搜索存在但不是核心交互

**核心问题**：XUNO 在首页放一个"大圆形语音按钮"（VOI-01），声称"按住录音+波形动画+松开发送"。这直接抄袭了微信的语音消息交互，但穿搭决策不是即时通讯。用户和伊伊的对话是"思考型交互"——用户需要看推荐、比较方案、做决策——不是"快说快答"的聊天。

**建议**：

- 保留语音按钮但**降级为辅助交互**，不要放在首页正中央
- 把语音作为"懒人模式"：当用户不想打字时的备选方案
- 优先投资在"快速回复按钮"（YIYI-05）和"滑动式风格逼近"上——这些才是穿搭场景的自然交互
- Sprint 阶段用 Android 原生 SpeechRecognizer 足够，但不要在 Demo 中重点展示语音，因为评委在会议室里听你说"按住说话"的体验不如直接展示对话

## 维度 3："零步决策"真实步骤数

**评分：3/10**
**标签：🔴 致命问题**

### 精确交互步骤审计

文档声称："用户在 Today Tab 打开 App 即获得伊伊主动推送的当日穿搭方案——零步决策，语音一步触达。"

这是完全不诚实的营销话术。以下是**首次用户的真实步骤**：

| 步骤 | 操作                                             | 耗时     | 累计     |
| ---- | ------------------------------------------------ | -------- | -------- |
| 1    | 下载并安装 App                                   | 30-60 秒 | 1 分钟   |
| 2    | 打开 App                                         | 2 秒     | 1 分钟   |
| 3    | 注册（邮箱/微信/短信）                           | 15-30 秒 | 1.5 分钟 |
| 4    | 进入 Onboarding Step 1：选场景                   | 8-12 秒  | 1.7 分钟 |
| 5    | Onboarding Step 2：画像                          | 10-15 秒 | 2 分钟   |
| 6    | Onboarding Step 3：风格+穿搭图                   | 12-18 秒 | 2.3 分钟 |
| 7    | Onboarding Step 4：让伊伊搭第一套 → 等待 AI 生成 | 5-10 秒  | 2.5 分钟 |
| 8    | 查看推荐的 3 套方案                              | 10-20 秒 | 3 分钟   |
| 9    | 选择/反馈                                        | 5 秒     | 3 分钟   |

**从打开 App 到获得穿搭方案：9 步，约 3 分钟。不是零步。**

即使去掉下载安装和注册（假设老用户），仍然是 **5 步，约 40-55 秒**：

1. 打开 App
2. 看到 Today Tab 的场景卡和 AI 摘要
3. 浏览今日方案（2-3 套）
4. 选择一套查看详情
5. 阅读推荐理由 / 触发试穿

**这和"零步"差距巨大。**

**对比竞品真实步骤**：

- 淘宝"猜你喜欢"：打开 App → 首页直接看到推荐 → **1 步**
- 小红书穿搭：打开 App → 首页信息流直接看到 → **1 步**
- 抖音购物：打开 App → 刷到带商品的视频 → **0 步**（被动接收）

**XUNO 唯一能做到"接近零步"的场景是**：老用户 + 已完成 Onboarding + 每天早上打开 App → 首页直接看到 3 套方案 → 这时是 **2 步**（打开 App + 浏览方案）。但这不是"零步"。

**为什么这个问题致命**：

- "零步决策"是整个产品叙事的基石
- 如果基石不成立，"体验壁垒替代技术壁垒"的叙事就崩了
- FINAL_PLAN 自己也承认（1.1 节）："所谓 1-2 步内获得穿搭决策在实际交互中需要至少 5-6 步"

**建议**：

1. 停止说"零步决策"，改为"**1 步触达**"——打开 App 首页就是方案
2. Onboarding 是一次性成本，不应该算进"日常决策"步骤——对老用户，真实体验确实是 1-2 步
3. 真正的差异化不是"步数最少"，而是**"决策质量最高"**——用户不需要在 10 套方案里纠结，伊伊已经帮你想好了

## 维度 4：策展型衣橱 vs 拍照录入

**评分：7/10**
**标签：🟢 改进建议（方向正确，执行有盲点）**

### "用户不需要拍照录入已有衣服"——这个假设是否成立？

**文档的论证**（17.2 节）：

- 旧定义：拍照录入已有衣服 -> 衣橱管理 -> 基于衣橱推荐
- 新定义：衣橱 = 用户在 XUNO 中的所有选择行为沉淀（收藏/想买/已购）
- 用户不需要"建设衣橱"，每次互动都自动沉淀为偏好信号

**这个决策的方向是对的**。原因：

1. **拍照录入是高摩擦行为**。研究表明，数字衣橱 App 中完成拍照录入的用户，衣物利用率从 30%提升到 69%——但问题是，大多数用户**根本完不成**录入。Acloset、Whering 等衣橱 App 的核心痛点就是"录了 3 件就放弃了"。
2. **中国用户更不会**。中国用户对"先用后享受"的耐心比欧美用户更低。要求用户拍 20 张照片才能获得好推荐，转化漏斗会断在 Step 1。
3. **策展型衣橱降低了启动成本**。用户只要"保存"和"选择"就能积累数据，这比拍照录入自然得多。

**但是——遗漏了一个核心场景**：

文档完全忽略了一个事实：**穿搭推荐的核心价值之一是"基于我已有的衣服做搭配"**。

看这段 FINAL_PLAN 的 Agent 交互设计：

> AI: "推荐这件针织衫配你衣柜里那条黑色直筒裤"

如果用户没有录入已有衣服，AI 怎么知道用户有"那条黑色直筒裤"？

**策展型衣橱解决的是"XUNO 推荐的商品用户喜不喜欢"（偏好信号），但没有解决"用户家里有什么衣服"（已有衣橱）。**

这两件事是不同的：

- **偏好信号**：用户喜欢黑色、简约风、M 码 —— 可以通过选择行为沉淀
- **已有衣橱**：用户衣柜里有 3 件黑 T 恤、1 条牛仔裤、1 件灰色西装外套 —— 必须通过某种方式录入

**如果不知道用户已有衣橱，XUNO 推荐的就是"你去买这些新衣服"，而不是"你已有的衣服可以这样搭"。后者才是日常穿搭决策的核心场景。**

**建议**：

1. 策展型衣橱的决策保留——作为初始启动策略，它是对的
2. 但在用户活跃 3-5 天后，通过**自然引导**而非强制要求，让用户拍照录入核心单品："你衣柜里有没有一件最喜欢的百搭单品？拍给我看看"——一次只录 1 件，低摩擦
3. 第三种路径：**从购买记录反推**——用户通过 XUNO 购买的商品自动进入衣橱。这是零摩擦的
4. 把拍照录入从"主路径"降为"渐进式增强"——不要求一次性录入，每次交互中自然积累

## 维度 5：6 个垂直场景优先级

**评分：8/10**
**标签：🔵 惊艳亮点**

### 场景选择评估

| 优先级 | 场景             | 评估         | 意见                                        |
| ------ | ---------------- | ------------ | ------------------------------------------- |
| P0     | 职场新人面试穿搭 | 选对了       | 比赛加分+社会价值+刚需+大厂不做             |
| P0     | 约会/社交穿搭    | 选对了       | 口碑传播核心+情感驱动+高频                  |
| P1     | 旅行打包穿搭     | 选对了       | 功能差异化+留存场景                         |
| P1     | 换季衣橱整理     | 选对了       | 年 4 次自然回流                             |
| P2     | 大码/非标体型    | 方向对但太早 | 市场有限+规则缺失（文档自己承认缺男性规则） |
| P2     | 升职/职业转型    | 选对了       | 高付费意愿                                  |

**面试场景是整个产品最亮的决策**。原因：

- 每年 900 万毕业生，90%不知道面试穿什么——数据冲击力强
- 互联网公司面试的 smart casual 场景规则明确、可编码、可展示
- 大厂不会专门做面试穿搭——太垂直
- 比赛评委对"解决青年就业"的社会价值天然有好感
- Agent 对话展示效果好："什么公司？什么岗位？预算多少？"

**遗漏的高价值场景**：

| 遗漏场景             | 价值               | 为什么该做                                         |
| -------------------- | ------------------ | -------------------------------------------------- |
| **孕妇穿搭**         | 刚需+高情感+无竞品 | 体型剧变+穿衣困扰+持续 6-9 个月+妈妈群体传播力极强 |
| **第一次见家长穿搭** | 刚需+社交传播      | "穿什么见对方父母"是小红书热门话题，具备天然传播性 |

**为什么"大码/非标体型"应该降级到 P3**：

1. 文档承认缺少男性穿搭规则、缺银发规则——连主流用户的规则都不完整，优先补长尾用户不合理
2. 大码用户需要特殊的推荐算法调优和尺码数据库，48 小时 Sprint 做不了
3. 大码用户群体忠诚度高是假设，不是数据——需要先证明主流场景成立

## 维度 6：与淘宝/抖音/小红书 AI 穿搭对比

**评分：6/10**
**标签：🟠 重要风险**

### "体验壁垒"经得起实测吗？

**文档声称的体验差距**（FINAL_PLAN 11.1 节）：

| 大厂           | 问题         | 用户感受           |
| -------------- | ------------ | ------------------ |
| 淘宝 AI 试衣间 | 4 层深埋     | "这功能存在？"     |
| 抖音 AI 换装   | 特定滤镜里   | "好玩但没用第二次" |
| 小红书 AI 穿搭 | 混在信息流里 | "分不清哪个是 AI"  |

**这个观察是准确的。** 大厂确实把 AI 穿搭当功能附件做，而不是核心体验。

**但"体验壁垒"的脆弱性**：

1. **大厂的迭代速度远超预期**。淘宝在 2024 年上线 AI 试衣间，2025 年升级。如果 XUNO 证明"首页即穿搭决策"的体验有价值，淘宝有足够的工程资源在 2-4 周内复制这个布局。

2. **"入口深"不是永久的**。大厂产品经理也在看竞品。如果他们发现把 AI 穿搭提到首页能提升转化率，改一个 Tab 的优先级对他们来说是 1 天的工作。

3. **真正的体验壁垒不在布局，在推荐质量**。如果 XUNO 的推荐还是基于 264 条手写规则+未 fine-tune 的 FashionCLIP，推荐质量不会比淘宝的协同过滤+用户购买数据好。淘宝有 10 亿用户的购买行为数据。XUNO 有 0。

4. **中国用户的忠诚度极低**。如果淘宝明天把 AI 试衣间提到首页，XUNO 的"体验优势"瞬间归零。中国 App 用户对新功能的忠诚度平均不超过 2 周。

**XUNO 真正经得起对比的差异化**：

| 差异化           | 能否持续 | 说明                                                        |
| ---------------- | -------- | ----------------------------------------------------------- |
| 对话式穿搭决策   | 中等     | 淘宝可以做，但他们不会做——因为这和"浏览-下单"的电商模式冲突 |
| 伊伊的人格化角色 | 中等     | 大厂做不出"有主见的朋友"——他们的 AI 是工具，不是人          |
| 穿搭记忆+进化    | **强**   | 如果做到 Level 4-5，用户积累的穿搭历史就是迁移成本          |
| 垂直场景深耕     | **强**   | 大厂不屑做面试穿搭，但 XUNO 可以做到极致                    |
| 无性别设计       | 弱       | 可复制，且主流用户不在乎                                    |

**建议**：

- 在 Demo 和商业计划书中，**不要说"大厂入口深"**——评委会说"他们改一下就好了"
- 要说"大厂的模式是'你来看商品'，XUNO 的模式是'AI 来找你'"——这是模式差异，不是布局差异
- 把核心叙事锚定在**穿搭记忆**（不可复制）而不是**交互设计**（可复制）

## 维度 7：Onboarding 转化率预估

**评分：5/10**
**标签：🟠 重要风险**

### 每一步的流失点分析

| 步骤                   | 预估完成率 | 累计留存   | 主要流失原因                                     |
| ---------------------- | ---------- | ---------- | ------------------------------------------------ |
| 打开 App               | 100%       | 100%       | —                                                |
| 注册                   | 70-80%     | 70-80%     | 强制注册是流失点 1；微信一键登录可缓解           |
| Step 1：选场景         | 90%        | 63-72%     | 8 个场景卡片选择不困难，但用户不理解"为什么要选" |
| Step 2：画像           | 85%        | 54-61%     | 身高体重是敏感信息；输入框调出键盘，体验中断     |
| Step 3：风格+穿搭图    | 80%        | 43-49%     | **最高认知负荷的步骤**；9 选 3 需要时间判断      |
| Step 4：让伊伊搭第一套 | 70%        | 30-34%     | AI 生成等待时间；3 套方案可能都不满意            |
| 完成 Onboarding        | —          | **30-34%** | —                                                |

**50 秒目标可行性**：ONBOARDING_DESIGN.md 的分析说"50 秒有野心但可实现"。这是乐观估计。真实中位数更可能在 55-70 秒。

**关键流失点分析**：

**流失点 1：Step 3 是瓶颈（12-18 秒，最高认知负荷）**

9 张穿搭图"选 3 张喜欢的"——问题不在时间，在用户不知道"我在选什么"。FashionCLIP 嵌入提取对用户是隐形的，用户只看到 9 张图。如果图片风格覆盖不够广（比如都是偏女性的穿搭），男性用户会困惑："没有一张是我会穿的。"

ONBOARDING_DESIGN.md 自己警告了这个问题："如果所有 9 张图来自女装目录，FashionCLIP 嵌入会聚集在女性编码区域。"但解决方案——"必须平衡性别表达覆盖"——只是原则，没有具体的图片选择策略。

**流失点 2：Step 4 是隐藏黑洞**

"让伊伊搭第一套"听起来很美。但实际执行链路是：

1. 用户等 AI 生成（3-8 秒）
2. 看到 3 套方案——基于冷启动数据，质量可能不高
3. 如果 3 套都不满意 -> 用户心态是"折腾半天就这？"
4. 没有明确的"跳过"出口——用户被困在这里

如果 Batch 1 推荐质量低（CTR<5%），Step 4 的完成率可能跌到 50%以下，总 Onboarding 完成率降到 20%。

**流失点 3：没有"先看再注册"选项**

当前架构要求注册 -> Onboarding -> 才能看到任何推荐。NN/g 研究明确建议："put users directly into the interface"。

**改进建议**：

1. Step 3 从 9 选 3 减为**6 选 2**——降低认知负荷（ONBOARDING_DESIGN.md 也建议了这个）
2. Step 4 增加"跳过，以后再说"按钮——给用户退路
3. 提供"无注册体验"路径——直接进入 Today Tab 看通用推荐，注册后个性化
4. 预生成 Onboarding 推荐方案——不要在用户等待时实时计算

## 维度 8：前 5 分钟体验情感曲线

**评分：6/10**
**标签：🟠 重要风险**

### 从打开到离开的完整用户体验分析

FINAL_PLAN 18.3 描绘了理想的前 5 分钟：

```
0:00  打开App → 伊伊："嗨！我是伊伊" → 好奇+期待
0:30  4步Onboarding → 有点麻烦但能接受 → 微降
2:00  看到第一套个性化推荐 → 期待实现 → 上升
2:30  和伊伊互动 → 有趣！ → 高点
4:00  保存了一套喜欢的搭配 → 满足 → 持续高位
4:30  伊伊："明天12°C，我会提前帮你准备好" → 期待明天 → 离开时有钩子
```

**理想的情感曲线**：平 → 微降 → 上升 → 高点 → 满足 → 期待

**现实中的情感曲线**：

```
0:00  打开App → 看到注册/登录页 → "又要注册？" → 微降
0:15  注册完成 → 进入Onboarding → "还要填信息？" → 继续降
0:30  Step 1 选场景 → "通勤、约会、休闲...好吧" → 平
0:45  Step 2 身高体重 → "为什么要知道我多重？" → 不适
1:00  Step 3 看穿搭图 → "这些图不是我的风格..." → 微降
1:20  Step 4 等伊伊生成 → [转圈等待] → 焦虑
1:30  看到3套推荐 → "嗯...也就那样吧" → 失望
2:00  选择了一套 → "先试试" → 勉强
2:30  跟伊伊对话 → 回复慢/回复不相关 → 烦躁
3:30  试穿效果 → 质量一般 → 进一步失望
4:30  退出 → "再看看吧" → 中性偏低
```

**3 个关键断裂点**：

**断裂点 1：Onboarding 中没有价值预览（0:00-1:20）**

用户在做 4 步选择时，没有看到任何实际的推荐效果。他们不知道"选这些场景有什么用"、"选这个风格会给我推荐什么"。这是一段长达 1 分 20 秒的纯投入-零回报期。

修复：在 Step 1 选完场景后，立即闪现一个"基于你的选择，伊伊会这样推荐"的预览——让用户提前看到价值。

**断裂点 2：首次推荐质量决定了情感走向（1:30-2:00）**

如果 Batch 1 推荐的 3 套方案质量不高，情感曲线就从这里开始一路向下，不会再恢复。这是"第一印象"——没有第二次机会。

冷启动推荐依赖规则引擎+Mock 数据。如果：

- Mock 数据只有 100 条（FND-05 的目标），场景覆盖不全
- 规则引擎的 hardcoded 简化版覆盖不了用户的体型/风格组合
- FashionCLIP 种子只有 2-3 张图，嵌入精度有限

那么"嗯也就那样"而不是"哇这个不错"是大概率结果。

**断裂点 3：伊伊对话响应质量（2:30-3:30）**

伊伊的人格 Prompt（YIYI-03）设计得很好——"温柔但有主见的朋友"。但：

- 对话状态机（YIYI-01）尚未实现，当前是简单的 prompt-in-response-out
- 如果 LLM 回复慢（GLM-4-Flash 延迟不稳定），用户等 3 秒以上就会烦躁
- 如果回复不相关（没有上下文记忆），用户会觉得"这 AI 不靠谱"

**建议**：

1. Onboarding 中加入**价值预览**——选完场景后立刻展示一个模拟推荐
2. Batch 1 推荐必须**人工精选**——不要完全依赖规则引擎，对最常见的 5 种 Profile 手工准备"黄金推荐"
3. 伊伊前 3 轮对话使用**预设回复模板**，不调 LLM——保证响应速度和回复质量
4. 3 轮之后切换到 LLM——此时用户已经建立了基本信任

## 最后的话

这份报告的基调是残酷的，但残酷不等于否定。

XUNO 的产品团队做了一个大多数团队做不到的事：**在写第一行代码之前就想清楚了产品的差异化叙事、用户模型、交互范式和商业化路径。** 42 项冻结决策、6 层用户画像、3 层推荐管道、6 个垂直场景——这些规划的质量在学生创业项目中是顶级的。

但规划的质量不等于产品的质量。当前最大的风险是：**团队把"规划完成"当成了"产品完成"**。文档里描绘的主动 Agent、沉浸式对话、穿搭记忆——这些在代码里一行都没有。48 小时 Sprint 的目标是把文档变成可运行的 Demo，但 5 个 Phase、41 个 REQ、3 个并行 Agent——这个执行计划本身就是一颗定时炸弹。

**如果只能记住一件事**：首次推荐质量决定生死。Onboarding 最后的"让伊伊搭第一套"是用户对 XUNO 的第一印象——如果这 3 套推荐质量不高，用户不会给第二次机会。不要依赖规则引擎+Mock 数据的自动输出，为最常见的 Profile 手工准备推荐方案。

**规划是 A，执行是 B+，但用户只会看到你交付的那个版本。**
