# 寻裳 XUNO — Demo 演示备用方案

> **用途**: 当实时 Demo 出现问题时，快速切换到备用方案，确保演示不中断
> **原则**: 评委不知道你切换了备用方案，就是成功的备用方案

---

## 风险等级评估

| 风险          | 概率 | 影响 | 备用方案编号 |
| ------------- | ---- | ---- | ------------ |
| 网络断连      | 中   | 高   | Plan B-1     |
| App 崩溃/闪退 | 中   | 高   | Plan B-2     |
| LLM 响应超时  | 高   | 中   | Plan B-3     |
| 投屏失败      | 低   | 高   | Plan B-4     |
| 模拟器卡顿    | 中   | 中   | Plan B-5     |

## Plan A: 标准实时演示

**设备**: iPhone/Android 手机 + 投屏
**流程**: 按 `XUNO-DEMO-SCRIPT.md` 逐秒执行
**前提**:

- App 已安装并登录
- Onboarding 已完成（测试账号）
- 网络稳定（WiFi + 4G 热点双备份）

---

## Plan B-1: 网络断连

**触发条件**: WiFi 断开，4G 也无法连接

**应对步骤**:

1. 不慌张，自然说: "我们看下离线模式的体验"
2. App 应该有基本的离线缓存（推荐结果预加载）
3. 展示缓存的推荐结果和已记忆的偏好
4. 如果完全无缓存，切换到 Plan B-2

**预防措施**:

- 演示前预加载所有推荐数据
- 确保"面试"和"约会"两个场景的推荐都已缓存
- 对话历史已本地存储
- 在测试账号上提前走完整个推荐流程

---

## Plan B-2: 预录视频播放（核心备用方案）

**触发条件**: App 崩溃、网络完全断连、任何导致无法实时演示的情况

**应对步骤**:

1. 自然说: "为了确保大家看到最流畅的体验，我准备了一段录屏"
2. 切换到视频播放（PPT 中嵌入的 mp4）
3. 视频播放期间，口述旁白（见下方视频脚本）
4. 视频结束后切回 PPT 继续演讲

### 预录视频规范

**技术参数**:

- 分辨率: 1920x1080 或 1080x1920（竖屏手机）
- 帧率: 30fps
- 格式: MP4 (H.264)
- 文件大小: < 100MB
- 时长: 2:20（与 Demo 脚本完全对齐）

**录制工具**:

- iOS: 系统录屏（控制中心 → 屏幕录制）
- Android: `adb shell screenrecord` 或 AZ Screen Recorder
- 模拟器: OBS Studio 录制模拟器窗口

**录制要求**:

- 去除所有加载等待时间（剪辑时加速或跳过）
- 确保伊伊的对话文字清晰可读
- 推荐结果的图片要高清
- 雷达图动画要完整展示
- 记忆能力的对话气泡要停留足够久

**后期处理**:

- 剪辑掉所有空白和等待
- 添加必要的文字标注（如"匹配度 88%"的大字）
- 如果需要，添加字幕
- 关键"哇"时刻添加放大效果

## Plan B-3: LLM 响应超时

**触发条件**: 伊伊回复慢（>5 秒无响应）

**应对步骤**:

1. 不等待，自然说: "伊伊正在思考，我们先看已生成的推荐"
2. 滑动到推荐结果区域（如果已有部分加载）
3. 如果完全无响应，说: "网络波动，我们看上次的推荐记录"
4. 展示历史推荐结果
5. 如果持续超时，切换到 Plan B-2

**预防措施**:

- 演示前预热 LLM（先发几条测试消息）
- 使用 GLM-4-Flash（响应最快）
- 确保 Redis 缓存中有上一次的推荐结果

---

## Plan B-4: 投屏失败

**触发条件**: 投屏软件无响应 / HDMI 线问题

**应对步骤**:

1. 拿起手机，直接对着评委展示（近距离演示）
2. 说: "我直接给大家看"
3. 如果场地有摄像投影，请工作人员切到手机摄像头
4. 如果无法展示手机，切换到 Plan B-2（PPT 中的视频）

**预防措施**:

- 提前测试投屏（至少 30 分钟前）
- 准备 HDMI 线 + 无线投屏双方案
- 备一根 Type-C 转 HDMI 线
- 在 PPT 中嵌入视频作为终极备用

---

## Plan B-5: 模拟器卡顿

**触发条件**: 使用模拟器时帧率低/卡顿

**应对步骤**:

1. 降低模拟器分辨率
2. 关闭不必要的后台进程
3. 如果持续卡顿，切换到 Plan B-2

**预防措施**:

- 使用真机而非模拟器
- 模拟器分配足够内存（8GB+）
- 预加载所有资源

---

## Plan B-6: 手机没电

**触发条件**: 手机电量 < 10%

**应对步骤**:

1. 立即切换到 Plan B-2（PPT 视频）
2. 同时给手机充电

**预防措施**:

- 演示前充满电（100%）
- 准备充电宝
- 准备备用手机（同账号已登录）

---

## 应急响应时间线

| 问题发生后 | 行动                           | 时间限制 |
| ---------- | ------------------------------ | -------- |
| 0-2 秒     | 识别问题类型                   | 立即     |
| 2-5 秒     | 自然过渡（不慌张）             | 3 秒内   |
| 5-10 秒    | 启动对应 Plan B                | 5 秒内   |
| 10 秒+     | 继续演示（不能停顿超过 10 秒） | 10 秒内  |

**核心原则**: 评委不知道你切换了备用方案 = 成功

---

## 最终建议

1. **优先使用 Plan A**（实时演示）—— 真实感最强
2. **Plan B-2（视频）准备到 100%**—— 这是最可靠的备用方案
3. **Plan C（纯 PPT 截图）永远有**—— 确保任何情况都能完成演示
4. **提前彩排 3 次以上**—— 包括"出问题后切换备用方案"的彩排
5. **录制视频时使用"最佳状态"**—— 后期剪辑去掉所有不完美
