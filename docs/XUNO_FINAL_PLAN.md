## 1. 创新性审计

### 1.1 Today Tab "决策优先" — 评分: 5/10

**当前状态**: 概念方向正确，但实现只是"换个首页布局"。

**犀利的质疑**:

- Google Now (2012)、Cladwell、Shine 等 App 都尝试过"今天穿什么"作为首页。**它们要么死了要么转型了。** 为什么 XUNO 不会重蹈覆辙？
- 时尚消费的本质是**情感驱动和灵感驱动**，不是功能决策。小红书的成功证明了"发现 → 喜欢 → 购买"远比"决策 → 执行"符合用户心理。
- 当前 Today Tab 的实现：天气卡 + 2-3 套搭配 + AI 一句话摘要。**这不就是一个带天气上下文的推荐 Feed 吗？** 和淘宝"猜你喜欢"加个天气标签有什么本质区别？
- 所谓"1-2 步内获得穿搭决策"在实际交互中需要：打开 App → 选择场景 → 等待推荐 → 查看搭配详情 → 读解释 → 决定试穿/收藏。这至少是 5-6 步，不是 1-2 步。

**改进方案**:

| 改进                                                                                  | 效果                                           | 难度 |
| ------------------------------------------------------------------------------------- | ---------------------------------------------- | ---- |
| **智能日历集成**: 读取用户日历事件，主动推送"明天有面试，推荐正装搭配"                | 从"被动等待用户来问"变为"主动告诉用户该穿什么" | 中   |
| **场景感知推送**: 基于位置+天气+时间，无需用户操作，打开 App 就看到当前场景的最优搭配 | 真正的 0 步决策                                | 低   |
| **穿搭记忆+进化**: 记录用户每次选择，构建"个人穿搭偏好曲线"，推荐越来越精准           | 差异化壁垒                                     | 中   |

**改进后预期评分: 8/10** — 从"换个布局"变为"真正理解用户当下需求的主动决策引擎"。

### 1.2 无性别 Onboarding — 评分: 4/10

**当前状态**: 进步性的包装，架构上只是重命名。

**犀利的质疑**:

- `garmentPreference.lowerBody: "pants" | "skirts" | "both"` — 这本质上就是性别代理变量。在中国市场，选择"skirts"的用户 95%+ 是女性。**改名不等于创新。**
- 真正的创新应该是：构建一个**连续的穿搭风格空间**，性别在这个空间里根本不是一个维度。当前的实现仍然是用分类变量做分桶，只是把桶名从"男/女"改成了"裤/裙"。
- 6 层用户画像模型设计得很专业，但每层都是**分类变量**。真正的突破应该使用**连续嵌入表示**——用向量表示用户的风格偏好，而不是用枚举值。
- 在中国市场宣传"无性别"理念是一把双刃剑：**可能获得评委的包容性加分，但可能疏远主流用户群体。**

**改进方案**:

| 改进                                                                                            | 效果                      | 难度 |
| ----------------------------------------------------------------------------------------------- | ------------------------- | ---- |
| **FashionDNA 连续嵌入**: 用用户选择的穿搭图 + 行为数据生成一个 128 维风格向量，替代所有分类字段 | 真正的去性别化 + 技术深度 | 高   |
| **自适应 Onboarding**: 根据前几步的选择动态调整后续问题，而非固定 4 步                          | 转化率提升                | 中   |
| **论文级论证**: 将 6 层画像模型写成学术论文投稿，增加学术含金量                                 | 比赛加分                  | 中   |

**改进后预期评分: 7/10** — 从"政治正确包装"变为"有学术支撑的架构创新"。

### 1.3 三层推荐管道 — 评分: 4/10

**当前状态**: 标准的 2024 年推荐系统架构模式，零创新。

**犀利的质疑**:

- Rules → Vector Search → LLM Explanation 是**当前推荐系统的标配做法**。任何上规模的推荐团队都在用类似的架构。
- FashionCLIP 是 patrickjohncyh 发表在 CVPR Workshop 2022 的模型。直接拿来用，没有 fine-tune，没有改进。评委问"你们有什么技术创新"时，答案是"我们用了别人的模型"。
- SASRec 来自 Kang & McAuley 2018 的论文。同样是拿来即用。
- 规则引擎的 264 条 JSON 规则是手工编写的，**不可扩展，不可学习，不可泛化**。
- 文档承认砍掉了协同过滤和知识图谱因为"伪实现"。这等于承认：**核心推荐能力只依赖于一个开源视觉模型 + 一个开源序列模型 + 手工规则。**

**改进方案**:

| 改进                                                                                                      | 效果                         | 难度       |
| --------------------------------------------------------------------------------------------------------- | ---------------------------- | ---------- |
| **ChineseFashionCLIP Fine-tune**: 在中国时尚数据上微调 FashionCLIP，解决 Farfetch 数据偏见 + 适应中国审美 | 技术壁垒 + 论文价值          | 高(2-3 周) |
| **规则学习化**: 将手工规则转化为可学习的 soft constraints，让模型从用户反馈中自动调整规则权重             | 真正的"AI 驱动"而非"AI 辅助" | 高         |
| **Contrastive Outfit Learning**: 训练一个搭配协调度模型（不是用现成的），学习"这套搭配为什么好看"         | 独家技术                     | 高(4-6 周) |

**改进后预期评分: 8/10** — 从"集成别人的模型"变为"有自己的模型创新"。

### 1.4 未考虑的颠覆性技术/交互

| 技术                              | 为什么重要                                                                  | 当前项目是否考虑       |
| --------------------------------- | --------------------------------------------------------------------------- | ---------------------- |
| **多模态 LLM (Qwen-VL / GLM-4V)** | 可以用一张照片理解整套穿搭风格、材质、搭配逻辑，替代整个规则引擎            | 否                     |
| **生成式穿搭 (Diffusion Models)** | 不是"试穿"而是"生成你穿这套衣服的样子"，质量远超当前虚拟试穿                | 否                     |
| **主动式 AI Agent**               | 不是用户问"今天穿什么"，而是 AI 主动说"你明天有会议，我帮你准备了 3 套搭配" | 否(文档提到但未规划)   |
| **个人时尚知识图谱**              | 记录用户的每次穿搭选择，构建个人风格进化曲线，预测未来偏好变化              | 否                     |
| **端侧小模型 (Qwen2.5-0.5B)**     | 隐私敏感的体型/风格推理在端侧完成，零上传                                   | 否(只考虑了 MediaPipe) |
| **实时时尚趋势 API**              | 将全网时尚趋势信号融入推荐，让推荐"不过时"                                  | 否                     |

## 2. 技术含金量评估

### 2.1 评委/投资人视角 — 评分: 5/10

**评委看到的技术叙事**:

> "我们用 FashionCLIP 做视觉相似度检索，用 SASRec 做序列推荐，用规则引擎做兜底，用 GLM-4-Flash 做解释生成。"

**评委的内心独白**:

> "所以你把三个开源模型接在一起？哪个是你自己做的？"

**残酷的事实**:

- **没有自研模型** = 没有技术壁垒
- **没有 Benchmark** = 无法证明效果比竞品好
- **没有消融实验** = 无法证明每个组件的贡献
- **没有用户实验** = 无法证明推荐质量
- **没有论文发表** = 没有学术认可

### 2.2 "缝合"还是"架构"？

**当前状态: 高级缝合。**

一个"架构"应该有：

1. 统一的表示空间（当前：三个模型各自输出，加权拼接）❌
2. 端到端可优化（当前：各模块独立，权重手动设定）❌
3. 可度量的反馈闭环（当前：推荐归因表存在但未实现）❌
4. 可验证的假设（当前：CTR 预期是理论值，无验证机制）❌

**改进方案**:

| 改进                                                                                          | 预期效果           | 投入   |
| --------------------------------------------------------------------------------------------- | ------------------ | ------ |
| **统一 Embedding Space**: 将 FashionCLIP 输出和用户行为嵌入映射到同一向量空间，真正的联合检索 | 推荐质量可量化提升 | 2-3 周 |
| **A/B Testing Framework**: 从第一天就埋入实验框架，每个推荐都有 experiment_id                 | 数据驱动迭代       | 1 周   |
| **Benchmark Suite**: 构建一套标准评估集（100 用户 × 20 场景），定期跑推荐质量评估             | 比赛展示材料       | 1 周   |
| **Ablation Study**: 对比 Rules-only / Rules+CLIP / Rules+CLIP+SASRec 的效果差异               | 技术深度证明       | 3-5 天 |

### 2.3 48 小时 Demo 技术展示力 — 评分: 6/10

**能展示的**:

- 4 Tab 导航 + Today 决策首页 ✅
- AI 对话式造型师 ✅
- 基础虚拟试穿 ✅
- 无性别 Onboarding 流程 ✅

**无法展示的（但评委可能问的）**:

**48 小时 Demo 的竞争力**: 中等偏上。能跑起来、能看、能交互，但缺乏"技术深度感"。

## 3. 商业模式硬伤

### 3.1 免费依赖链的脆弱性 — 评分: 3/10

**三个致命假设**:

| 假设                     | 现实                                                                                             | 风险等级 |
| ------------------------ | ------------------------------------------------------------------------------------------------ | -------- |
| GLM-4-Flash 永远免费     | 智谱的免费策略是获客手段，随时可能调整。历史上百度文心、通义千问都经历过免费 → 限流 → 收费的过程 | 🔴 致命  |
| 虚拟试穿成本可控         | 豆包/GLM 图像生成 0.05 元/次，1000 DAU × 50% × 1.5 次/天 = 1,125 元/月。已远超原预算             | 🔴 致命  |
| Windows 开发机 7×24 稳定 | 无 UPS、Windows Update、断电、ISP 问题。理论 99.8% 实际可能 95-97%                               | 🟡 高    |

**成本黑洞分析**:

文档声称 100 DAU 月成本 ~400 元。拆解：

```
电费: 100-150 元/月 (可信)
虚拟试穿: 100 用户 × 50%使用率 × 1.5次/天 × 30 天 × 0.05 元 = 1,125 元/月
  → 已经远超总预算!
如果试穿成本计入:
  → 实际月成本: 1,625-1,800 元，不是 400 元
```

**文档的"端侧推理节省 62%"是不诚实的** — 端侧推理只是把 CIELAB + MediaPipe 放到端上，这两项本来就几乎不花钱。真正的成本（图像生成 API）完全没有端侧替代方案。

**修正后月度成本模型（1000 DAU）:**

| 成本项                           | 金额          | 来源                                                 |
| -------------------------------- | ------------- | ---------------------------------------------------- |
| 月基础设施（RTX 4060 本地+域名） | 350 元        | 实测                                                 |
| 虚拟试穿 API                     | 1,125 元      | 1000DAU×50%×1.5 次/天 ×30 天 ×0.05 元，豆包/GLM 定价 |
| LLM API（备用）                  | 100 元        | GLM-4-Flash 免费，备用付费                           |
| 域名+杂项                        | 50 元         |                                                      |
| **月总成本**                     | **~1,625 元** |                                                      |

**改进方案**:

| 改进                                                                             | 效果           |
| -------------------------------------------------------------------------------- | -------------- |
| **GLM 备选链**: 准备通义千问免费额度 + 本地 Qwen2.5-0.5B 降级方案                | LLM 成本为零   |
| **试穿分级策略**: 免费用户只看搭配效果图（不生成试穿图），付费用户才生成真实试穿 | 成本降低 70%   |
| **预缓存热门试穿**: 凌晨批处理生成 Top 100 商品的试穿图，命中时零成本            | 免费试穿零成本 |
| **成本预警系统**: 每日 API 调用量和费用监控，超阈值自动降级                      | 防止费用失控   |

### 3.2 付费转化率不现实 — 评分: 3/10

**文档声称**: 3-5% 付费转化率，2-4 元 ARPU/月

**现实检验**:

| 对标                   | 付费转化率   | 说明                   |
| ---------------------- | ------------ | ---------------------- |
| 中国 App 平均 (工具类) | 0.5-1.5%     | XUNO 本质是工具类      |
| 小红书 (内容社区)      | <1% (VIP)    | 但有广告收入           |
| 美图秀秀 (AI 美颜)     | 1-2%         | 比 XUNO 用户需求更刚性 |
| Keep (健身)            | 2-3%         | 但有极强的内容壁垒     |
| **XUNO (AI 穿搭)**     | **0.8-1.5%** | **更现实的目标**       |

**一次性购买替代月订阅（修正后定价）:**

- 色彩报告: 6.9 元/份（冲动消费价，来源：对标 MBTI 测试定价）
- 体型分析报告: 9.9 元/份（对标 MBTI 测试）
- 胶囊衣橱方案: 14.9 元/份
- **不做月订阅** — 报告是一次性价值产品，用户买完没有续费理由

**修正后 ARPU 测算:**

```
付费转化率: 1.2%（取0.8-1.5%中值，来源：中国工具类App行业均值）
加权均价: ~10.5元（6.9×40% + 9.9×35% + 14.9×25%）
月ARPU: 1.2% × 10.5 = 0.126元/用户/月
3000MAU月内容产品收入: 3000 × 0.126 = 378元
```

**改进方案**:

| 改进                                                                                             | 效果                   |
| ------------------------------------------------------------------------------------------------ | ---------------------- |
| **一次性购买替代订阅**: 色彩报告 9.9 元/份，胶囊衣橱 19 元/份，取消月订阅                        | 更符合中国用户消费心理 |
| **连续价值订阅**: 每周自动生成"下周穿搭计划"（基于天气+日历+衣橱），这才是续费理由               | 订阅有持续价值         |
| **免费增值转付费增值**: 先让用户免费体验完整功能 7 天，然后降级，比直接展示付费墙转化率高 3-5 倍 | 转化率提升             |
| **实物绑定**: 和淘宝客联动，"买满 199 元送一个月会员"，用电商佣金补贴会员成本                    | 降低付费门槛           |

### 3.3 电商佣金严重高估 — 评分: 2/10

**文档声称**: 8-12% 佣金

**现实数据**:

| 平台            | 时装品类实际到手佣金率 | 说明                                            |
| --------------- | ---------------------- | ----------------------------------------------- |
| 淘宝客 (女装)   | 2-5%                   | 大部分商品 3% 左右，来源：2026 淘宝联盟官方规则 |
| 淘宝客 (男装)   | 2-4%                   | 比女装更低                                      |
| 淘宝客 (鞋包)   | 2-5%                   | 品牌商品较高                                    |
| 京东联盟 (服饰) | 8-15%                  | 新账号首 3 月有考核期，来源：京东联盟官方规则   |
| 得物            | 无联盟计划             | 文档已确认移除                                  |

**8-12% 只存在于特定促销活动**（双十一等），不是常态。将促销峰值作为商业计划的基准值是严重的财务错误。

**修正后的 ARPU 测算:**

```
假设:
  淘宝客到手佣金率: 3.5%（来源：2026淘宝联盟官方规则）
  京东联盟到手佣金率: 10%（来源：京东联盟官方规则）
  混合加权平均: ~5%（淘宝70%+京东30%）
  付费用户月均购买: 200 元 (服装类平均)
  购买用户占比: 8% (修正后估计)

月佣金 ARPU = 200 × 5% × 8% = 0.8 元/用户/月
3000MAU月佣金收入: 3000 × 0.8 = 2,400元 → 修正为1,680元（购买率8%×200元×3.5%淘宝为主）

不是文档声称的 5-15 元ARPU。
```

**改进方案**: 电商佣金不应作为主要收入来源。重构为"内容产品一次购买 + 增值服务"为主，佣金为辅。

## 4. 竞争壁垒质疑

### 4.1 总体壁垒评分: 2/10

**如果抖音/小红书明天上线 AI 穿搭功能，XUNO 凭什么活下来？**

文档没有回答这个问题。我来替它回答：**活不下来，除非在巨头进入前建立起深度用户数据壁垒。**

### 4.2 逐项壁垒分析

| 文档声称的壁垒          | 现实                                         | 评分     |
| ----------------------- | -------------------------------------------- | -------- |
| "决策优先"产品形态      | 可复制，大厂 1-2 周可做                      | 1/10     |
| FashionCLIP 视觉理解    | 开源模型，任何人可用                         | 1/10     |
| SASRec 序列推荐         | 2018 论文，广泛使用                          | 1/10     |
| 264 条时尚规则          | 手工编写，不可扩展，可被 LLM 替代            | 2/10     |
| 无性别设计              | 概念容易被模仿                               | 2/10     |
| 淘宝客/京东联盟商品数据 | 任何人都可以接入                             | 1/10     |
| **用户画像深度数据**    | **这是唯一潜在壁垒，但需要大量用户才能建立** | **5/10** |

### 4.3 真正的壁垒在哪里？

**不在技术，在数据。**

XUNO 唯一可能的壁垒路径：

1. 获取前 1000 个深度用户
2. 每个用户贡献：体型数据 + 穿搭偏好 + 行为序列 + 试穿反馈
3. 这些数据构建出**其他人没有的用户-穿搭匹配知识**
4. 这知识体现在微调后的 FashionCLIP 权重里
5. 微调后的模型才是壁垒

**但当前计划完全没有"数据飞轮"的设计。** 没有用户反馈收集机制，没有模型迭代更新计划，没有持续学习的架构。

**改进方案**:

| 改进                                                                                      | 效果       |
| ----------------------------------------------------------------------------------------- | ---------- |
| **数据飞轮设计**: 每个用户的试穿反馈 → 重新训练 SASRec → 更好的推荐 → 更多用户 → 更多数据 | 真正的壁垒 |
| **FashionCLIP Fine-tune**: 用收集的中国用户数据微调，产生专有模型                         | 技术壁垒   |
| **用户生成穿搭方案 (UGC)**: 让用户创建和分享穿搭方案，构建内容壁垒                        | 内容壁垒   |
| **垂直场景深耕**: 不做"全人群"，做"大学毕业生职场穿搭"等垂直场景，大厂不屑做的小市场      | 市场壁垒   |

### 6.2 Top 3 必须改的致命问题

**致命问题 #1: 没有技术护城河**

当前项目的三个"创新"全部可以被竞品在 2-4 周内复制。评委问"你的核心竞争力是什么"时，如果答案是"我们用了 FashionCLIP"，这等于在说"我的核心竞争力是别人的核心竞争力"。

**必须做的**: ChineseFashionCLIP Fine-tune。在中文时尚数据上微调 FashionCLIP，产生一个专有模型。这个模型对特定场景的准确度应该显著超过原版。这给了你"只有我们有的东西"。

**致命问题 #2: 商业模型建立在虚假数字上**

8-12% 佣金率、3-5% 付费转化率、GLM 永远免费 — 这三个假设任何一个崩塌都会导致整个商业模型失效。

**必须做的**:

1. 将佣金率修正为 3%，重新测算 P&L
2. 将付费转化率目标下调到 1-2%，设计对应的成本结构
3. 准备 GLM 替代方案（通义千问 + 本地 Qwen）
4. 主收入来源从"电商佣金"转向"内容产品一次购买"

**致命问题 #3: 没有数据飞轮设计**

当前架构是"静态推荐系统"：模型不更新，规则不学习，用户数据不回流。没有数据飞轮意味着用户越多推荐越好的正循环不存在，壁垒永远建立不起来。

**必须做的**: 设计完整的 Feedback Loop：

```
用户行为 → 埋点收集 → 离线分析 → SASRetrain → FashionCLIP Fine-tune → 更好的推荐
```

把这个写进 Phase 8，并在 Demo 中展示这个闭环的设计（即使 48 小时内来不及实现）。

### 6.3 Top 3 最值得加的创新点

**创新点 #1: 主动式 AI 穿搭 Agent (Priority: P0)**

不是用户问"今天穿什么"，而是 AI 说："你明天上午有会议，气温 12°C，建议穿灰色西装外套配白衬衫。要不要看看效果？"

这是从"被动工具"到"主动助理"的质变。评委和投资人一听就知道这是下一代产品。

实现路径：

- 接入系统日历 API 读取事件
- 结合天气 API + 季节 + 用户衣橱
- 用 GLM-4V 生成搭配方案
- 推送通知（可做 Demo 展示）

48 小时内可以做：一个简化版的"明天的穿搭计划"，基于天气 + 固定场景。

**创新点 #2: ChineseFashionCLIP Fine-tune (Priority: P0)**

在中文电商商品数据 + 中国人穿搭图片上微调 FashionCLIP，产生专有模型。

为什么值得做：

- 技术壁垒：只有你有这个模型
- 学术价值：可以写论文
- 实际效果：原版 FashionCLIP 在 Farfetch 数据上训练，对中国审美理解不足
- 比赛加分：评委看到"自研模型"三个字会认真对待

实现路径：

- 淘宝客 Top 5000 商品图片 + 标签
- 小红书合规穿搭图片 + 风格标注
- FashionCLIP + LoRA 微调（RTX 4060 本地即可）
- 对比 Benchmark 证明提升

时间估算：数据准备 3-5 天 + 训练 2-3 天 + 评估 2 天 ≈ 1-2 周

**创新点 #3: 穿搭知识图谱 + 风格进化追踪 (Priority: P1)**

为每个用户构建一个个人穿搭知识图谱：

- 记录每次穿搭选择
- 追踪风格偏好变化趋势
- 预测未来可能喜欢的风格
- 可视化展示"你的风格进化之路"

为什么值得做：

- 差异化：没有任何竞品做"风格进化追踪"
- 用户粘性：用户能看到自己的变化，产生情感连接
- 数据壁垒：知识图谱越深，用户越难离开
- 展示效果：Demo 中展示一个虚拟用户 3 个月的风格变化曲线，极具冲击力

### 9.2 淘宝客佣金率修正

**文档声称 8-12%**。实际调研结果：

- **平台服务费在展示佣金之上额外扣除 10%**
- **推广者实际到手佣金率**: 淘宝客 **2-5%**（取中值 3.5%），京东联盟 **8-15%**（取中值 10%）
- 来源：2026 淘宝联盟官方规则 + 京东联盟官方规则

**修正**: 本文档 §3.3 和 §7.3 已按实际到手率修正。淘宝客 2-5%为保守但准确的基准。

```
AI: "看到你有面试！是什么类型的公司？"
用户: "互联网公司，产品经理岗"
AI: [展示 3 套搭配图] "互联网 PM 建议 smart casual：

AI: [方案A 变体] "200 元预算可以这样搭：
```

#### 场景 2: 约会穿搭（P0 — 口碑传播核心）

**Agent 交互流程**:

```
AI: "约会！什么场景？咖啡厅还是晚餐？"
用户: "下午咖啡"
AI: "轻松但有心的感觉。你喜欢偏干净利落还是温柔文艺？"
用户: [选择图片] "这种风格"
AI: [FashionSigLIP 分析用户选择的图片风格]
```

## 13. 沉浸式 Agent 交互设计 — XUNO 的核心体验

### 13.1 设计哲学：不是工具，是搭子

| 传统 App 交互         | XUNO Agent 交互                                   |
| --------------------- | ------------------------------------------------- |
| 用户选商品 → App 展示 | **AI 先开口："今天降温了，要不要看看保暖搭配？"** |
| 静态结果列表          | **对话式逐步逼近，每一步都有视觉变化**            |
| 试穿 = 上传+选品+等待 | **试穿 = 对话中随时说"看看效果"，1 步触发**       |
| 结果看完就结束        | **AI 追问："喜欢吗？要不要看看搭配的外套？"**     |
| 下次打开从零开始      | **AI 记得："上次你说不喜欢高领，这次换了圆领"**   |
| 无情感连接            | **"你上周那套约会搭配很好看！今晚有安排吗？"**    |

### 13.2 Agent 交互的 5 个层级

```
Level 1: 被动响应（当前大多数 App 的水平）
  用户问 → AI 答 → 结束

Level 2: 主动追问（XUNO 最低标准）
  用户问 → AI 答 → AI 追问 → 用户细化 → AI 给更好方案

Level 3: 场景感知（XUNO 目标标准）
  AI 感知场景（天气/日历/位置/时间）→ 主动开口 → 引导用户完成决策

Level 4: 风格学习（XUNO 壁垒标准）
  AI 记住用户偏好历史 → 主动调整推荐策略 → 越用越准 → 用户离不开

Level 5: 风格进化追踪（XUNO 终极标准）
  AI 理解用户的风格在变化 → 预测未来偏好 → 主动推荐新的可能性
  "你的风格越来越简约了，要不要试试 MUJI 风？"
```

### 13.3 关键交互创新

#### 创新 A: 视觉优先对话

每一步 AI 回复都**带图**。不是文字描述然后用户想象，而是直接展示视觉效果：

```
传统: "推荐你穿蓝色衬衫配卡其裤"
XUNO: [展示穿搭效果图] + [展示试穿效果] + "你觉得怎么样？"
```

**技术实现**: 预生成热门单品搭配图 + 实时试穿 API 结合。

#### 创新 B: 滑动式风格逼近

```
AI: "给你看两套搭配 [展示 A 和 B]"
用户: [左滑选 A]  ← 不需要文字，一个手势就行
AI: "了解，你偏利落风。[展示 C 和 D，都偏利落]"
用户: [选 D]
AI: [记忆偏好] "你偏好简约利落+深色系。以后推荐都按这个方向。"
```

**比 Onboarding 问卷更好**: 用户不需要在注册时告诉 App 自己喜欢什么，通过自然交互让 App 自己学会。

#### 创新 C: 衣橱上下文感知

```
AI: "推荐这件针织衫配你衣柜里那条黑色直筒裤"
     [展示：推荐单品 + 用户衣橱已有单品的搭配效果图]
用户: "那条裤子太旧了"
AI: "那要不要看看替代款？[推荐 2 条类似裤子，200 元以内]"
```

**壁垒**: 这个交互需要 AI 同时理解"推荐新商品"+"用户已有衣橱"+"两者如何搭配"。大厂的推荐系统和衣橱系统是分离的。

#### 创新 D: 穿搭日记 + 进化曲线

```
每周自动生成"穿搭周报"：
  - 本周穿了 5 套搭配
  - 最满意的一套：[展示图]
  - 风格分布：利落 60% / 休闲 40%
  - 趋势：比上个月更偏好深色
  - [可视化风格进化曲线图]
  - "下周要不要尝试一个新的风格方向？"
```

**为什么是壁垒**: 这份穿搭日记积累越多越不可替代。用户不可能在另一个 App 从零重建自己的穿搭历史。

## 14. 模型与数据策略升级

### 14.1 模型替换计划

| 组件     | 当前               | 升级到                                 | 理由                                          |
| -------- | ------------------ | -------------------------------------- | --------------------------------------------- |
| 视觉嵌入 | FashionCLIP (2022) | **Marqo-FashionSigLIP (2025 SOTA)**    | 全面超越，同样参数量                          |
| 序列推荐 | SASRec (2018)      | **SASRec + Positional Encoding 升级**  | 增加时间感知和季节感知                        |
| 规则引擎 | 264 条 JSON        | **LLM-as-Rule-Engine + 知识蒸馏**      | 规则不可扩展，用 LLM 生成规则后蒸馏为向量约束 |
| 试穿生成 | Doubao/GLM API     | **分级策略：预缓存 + API + 本地 SD**   | 成本控制                                      |
| AI 对话  | GLM-4-Flash        | **GLM-4-Flash + 穿搭领域 Prompt 工程** | 不换模型，换 Prompt 策略                      |

### 14.2 数据策略：三层飞轮

```
Layer 1: 冷启动数据（Demo 阶段）
  ├── 淘宝客 Top 5000 商品图片 + 标签
  ├── AI 生成的穿搭场景图（Stable Diffusion，自有版权）
  ├── 公开时尚数据集（DeepFashion, Polyvore）
  └── 创始人手动标注的 500 条"好搭配/坏搭配"判定

Layer 2: 用户行为数据（上线后）
  ├── 用户选择/跳过/收藏/购买行为
  ├── 对话中的偏好表达（"不喜欢高领""太正式了"）
  ├── 滑动式风格逼近的选择序列
  ├── 试穿后的满意度反馈
  └── 每个行为都带有 (用户Profile, 场景, 天气, 时间) 上下文

Layer 3: 模型迭代数据（增长期）
  ├── Layer 2 数据自动回流训练
  ├── FashionSigLIP 定期 Fine-tune（月度）
  ├── SASRec 序列模型周度重训练
  ├── "好搭配/坏搭配"分类器持续优化
  └── 每次迭代都跑 Benchmark 对比前后效果
```

### 14.3 训练策略

#### 策略 1: ChineseFashionSigLIP Fine-tune

```
基础模型: Marqo-FashionSigLIP (150M params)
训练数据: 淘宝客 5000 商品图 + DeepFashion 中文子集
训练方法: LoRA (rank=16, ~2M 可训练参数)
训练设备: RTX 4060 本地
训练时间: ~4-6 小时
评估指标: 搭配检索准确率、风格分类 F1、跨品类兼容度
```

**关键差异点**: Fine-tune 目标不是"更好的商品检索"，而是**"更好的穿搭兼容度理解"**。训练信号来自"这两件商品搭配在一起好不好看"，不是"这两件商品视觉上像不像"。

#### 策略 2: 偏好学习模型

```
目标: 学习"这个用户在什么场景下偏好什么风格"
训练信号: 用户在 Agent 对话中的每一次选择
模型: 轻量级 Transformer (5M params)
输入: [用户Profile向量] + [场景向量] + [候选商品向量]
输出: 偏好得分 0-1
更新频率: 每日增量训练
```

**这比 SASRec 更强**: SASRec 只学"你看过什么"，偏好模型学的是"你在什么场景下为什么选了 A 不选 B"。

#### 策略 3: 穿搭协调度模型（终极壁垒）

```
目标: 给任意两件/多件商品打一个"搭配协调度"分数
训练数据:
  - 正样本：Polyvore/用户创建的穿搭方案
  - 负样本：随机组合 + 用户跳过的推荐
模型: 双塔 + 交叉注意力 (10M params)
输出: 0-1 搭配协调度
用途: 替代手工规则引擎的兼容度打分
```

**这是真正的技术壁垒**: 一个训练好的"穿搭协调度模型"，不是规则引擎能比的。

### 14.4 数据收集创新

| 数据类型         | 收集方式                   | 隐私级别 | 用途           |
| ---------------- | -------------------------- | -------- | -------------- |
| 滑动选择序列     | Agent 对话中的滑动手势     | 低       | 偏好学习       |

### 17.2 衣橱重新定义（关键架构变更）

**旧定义**: 用户拍照录入已有衣服 → 衣橱管理 → 基于衣橱推荐搭配

**新定义**: 衣橱 = 用户在 XUNO 中的所有选择行为沉淀

```
衣橱内容:
├── AI 方案收藏：用户说"这套好看" → 保存完整搭配方案
├── 想买清单：用户点击"想买" → 保存单品
├── 已购清单：用户通过 XUNO 购买 → 自动记录
└── 吊牌扫码：用户扫品牌二维码 → 自动添加（有合作时）

衣橱自动沉淀，用户不需要"建设衣橱"
每次保存/收藏/购买 = 一个偏好信号 → 喂给推荐引擎
```

**架构影响**:

| 原设计                                 | 变更后                                               |
| -------------------------------------- | ---------------------------------------------------- |
| Onboarding Step 4: "拍照录入已有衣物"  | **删除**，替换为"选择你喜欢的 3 套 AI 推荐方案"      |
| 衣橱管理 = 拍照上传 + 分类浏览         | **衣橱 = 策展空间**，展示用户的选择偏好              |
| 缺口推荐基于已有衣物                   | 缺口推荐基于**用户选择偏好的空白**                   |
| Profile L5 Wardrobe Graph = ownedItems | L5 = savedOutfits + wishlistedItems + purchasedItems |
| "拍照添加到衣橱"入口                   | 保留但不作为主路径，改为"扫吊牌"或"从推荐保存"       |

**推荐管道适配**:

```
L6 衣橱互补层（修订）:

旧逻辑: "用户有黑色西装外套，推荐能搭配的裤子"
新逻辑: "用户保存了 3 套含西装外套的搭配 → 偏好正装场景
        → 但没有保存过休闲场景方案 → 休闲场景是缺口

从"物品互补"变为"偏好互补"——推荐用户还没探索过的风格方向。
```

## 18. 第二轮决策锁定

### 18.1 平台策略

| 阶段             | 平台                  | 说明                                 |
| ---------------- | --------------------- | ------------------------------------ |
| 48h Sprint       | React Native App      | 已有代码基础，Sprint 基于此          |
| Phase 2 (上线后) | **+ 微信小程序**      | 微信生态内传播，获客效率远超独立 App |
| 长期             | RN App + 小程序 + Web | 三端覆盖                             |

微信小程序优先级提升的理由：

- 微信内"帮朋友搭一套"裂变零摩擦
- 小程序分享到朋友圈/群的转化率比 App 下载高 10-50 倍
- 比赛评委和投资人可以直接扫码体验，不需要安装 App
- "扫吊牌二维码"功能天然适合小程序场景

### 18.2 额外创新功能（创始人选定）

按优先级排列：

| 优先级 | 功能                       | 价值                                       | 落地时间       |
| ------ | -------------------------- | ------------------------------------------ | -------------- |
| **P1** | **穿搭日历（周计划视图）** | 7 天搭配一目了然，主动 AI 的可视化载体     | Sprint 后 1 周 |
| **P1** | **拍照识图找同款**         | 获客钩子——"在街上看到好看的，拍照找同款"   | Sprint 后 2 周 |
| **P2** | **风格 DNA 社交匹配**      | "找到和你风格最像的人"——基于向量的社交发现 | Phase 3        |

**穿搭日历的详细设计**：

```
┌─────────────────────────────────────────┐
│  < 本周              穿搭日历        >  │
├──────┬──────┬──────┬──────┬──────┬──────┤
│ 周一  │ 周二  │ 周三  │ 周四  │ 周五  │ 周六  │
│ 15°C  │ 12°C  │ 14°C  │ 18°C  │ 20°C  │ 22°C  │
│      │      │      │      │      │      │
│ [搭配] │ [搭配] │ [面试] │ [搭配] │ [搭配] │ [约会] │
│ 图   │ 图   │ 图    │ 图   │ 图   │ 图   │
│      │      │      │      │      │      │
│ 休闲  │ 通勤  │ 面试! │ 通勤  │ 休闲  │ 约会♡ │
└──────┴──────┴──────┴──────┴──────┴──────┘
  → 点击任意一天可查看/修改搭配方案
  → AI 自动基于天气+日历+衣橱生成
  → 标注特殊事件（面试/约会/聚会）
```

为什么这个功能价值极高：

1. **主动 AI 的可视化载体** — 不再是"打开 App 看推荐"，而是"打开 App 看我的一周计划"
2. **每日打开的理由** — 每天早上看一眼今天的搭配
3. **比赛展示极具冲击力** — 评委看到一整周的搭配计划，立刻理解"主动 AI"
4. **自然积累数据** — 用户修改 AI 推荐方案的每一次操作都是偏好信号

**拍照识图找同款的设计**：

```
用户拍照（街头看到的好看穿搭）
  ↓
FashionSigLIP 编码图像
  ↓
Qdrant 向量检索最相似的商品
  ↓
展示 5 个同款/相似款 + 价格 + 购买链接
  ↓
"喜欢这套搭配？AI 帮你搭一套更适合你的版本"
  ↓
自然引导进入 Agent 对话
```

为什么是获客钩子：

1. 用户拍照找同款是**即时满足**——不需要注册就能用
2. 找到同款后自然引导"AI 帮你搭更好的" → 注册转化
3. "在街上拍照找衣服"这个行为本身就是社交货币，用户会分享

**风格 DNA 社交匹配的设计**：

```
用户 A 的 FashionSigLIP 向量 → 与所有用户的向量做余弦相似度
  → 找到最相似的 10 个用户
  → 展示他们的穿搭方案
  → "和你风格最像的用户还穿了这些"
```

壁垒：这不是基于社交图谱（微信/QQ 好友）的推荐，而是基于**风格图谱**的社交发现。大厂没有这个维度。

### 18.3 AI 角色：伊伊

**名字**: 伊伊（已确认）

**性格**: 温柔但有主见的朋友

```
伊伊说什么:
  ✅ "我觉得你穿深色更有气质，因为你的肤色偏暖"
  ✅ "明天降温了，别忘了穿外套"
  ✅ "等等，那件和你上次选的黑色西装不搭，换这件试试？"
  ✅ "这套有点冒险，但你要是敢穿一定很帅"
  ✅ "面试的话别穿牛仔裤，即使互联网公司也不太合适"

伊伊不说什么:
  ❌ "亲~""哦~""呢~"（淘宝客服感）
  ❌ "根据算法分析，推荐您..."（机器感）
  ❌ "您可以尝试探索更多可能性"（废话文学）

记忆能力（核心差异化）:
  - "上次你说不喜欢高领，以后都推荐圆领"
  - "你最近偏好深色系，要不试试换个方向？"
  - "你上周那套约会搭配很好看！今晚有安排吗？"
```

**推送策略**: 递减型

```
新用户（前 7 天）:
  每天 7:30 推送今日搭配 → 养成"早上看伊伊"的习惯
```

### 20.3 补充遗漏（10 项）

#### #1 TTS: 伊伊的声音

- Sprint: Edge-TTF（免费，微软语音引擎，中文质量好）
- Sprint 后: 讯飞自定义声线（录制伊伊专属声音）
- 声音人设: 25-28 岁温暖女声，略慢于日常对话，有情绪起伏

#### #2 对话状态机

```
GREET → CONTEXT → [SCENE|DIRECT|CHAT] → GENERATE
  → [满意→ACTION] [调整→REFINE→GENERATE] [换方向→CONTEXT]
  → WRAP_UP
```

异常处理: 用户放弃 → 温柔收尾 / 都不喜欢 → 引导描述偏好 / LLM 超时 → 规则推荐降级

#### #3 视觉设计体系

配色: 主色#C4956A(暖驼) + 辅色#2D3436(深炭灰) + 强调#E17055(暖橘) + 背景#FAFAF8(暖白)
伊伊形象: 暖驼色圆形 + 简笔画衣架图标（不做拟人头像）
圆角: 卡片 16px / 按钮 12px / 输入框 24px
间距基线: 8px

#### #4 体型敏感度（伦理红线）

核心原则: 描述服装，不描述身体。永远从"衣服特点"出发，不从"身体缺点"出发。

- ❌ "遮住粗腿" → ✅ "A 字裙的版型很衬你的比例"
- ❌ "显瘦" → ✅ "利落的剪裁让整体线条更流畅"
- 试穿失败归因于衣服，不归因于人
- 体型报告使用正面措辞，强调"适合什么"而非"避免什么"

#### #5 离线能力

离线可用: 缓存推荐(50 条) + 衣橱浏览 + 穿搭日历 + 规则引擎
离线不可用: AI 对话/向量检索/试穿/天气/拍照找同款
降级: 顶部"离线模式"提示 + 展示缓存内容 + 操作队列联网后同步

#### #6 金融模型

盈亏平衡: ~5000-8000 MAU（约第 5-7 个月，修正自原 3000MAU）
月成本基线: ~1,625 元（含虚拟试穿 API 1,125 元，此前版本遗漏此成本）

修正后 P&L:

```
3000MAU (~500DAU) 月度:
  内容产品收入: 3000 × 1.2% × 10.5元 = 378元
  电商佣金: 3000 × 8%购买率 × 200元客单 × 3.5%佣金 = 1,680元
  月总收入: ~2,058元
  月总成本: ~1,625元
  月净利润: ~433元

5000MAU (~830DAU):
  内容产品: 5,000 × 1.2% × 10.5 = 630元
  电商佣金: 5,000 × 8% × 200 × 3.5% = 2,800元
  月总收入: ~3,430元
  月成本: ~2,100元（试穿成本线性增长）
  月净利润: ~1,330元
```

LTV/CAC: 3-4x（健康区间）
商业叙事: "低盈亏平衡点的精益创业"而非"高增长高利润"

#### #7 市场分析

TAM: 中国 AI 穿搭决策 3 亿人
SAM: 活跃穿搭 App 用户中 20-30% ≈ 3000-5000 万
SOM: 第 1 年 1-5 万 → 第 2 年 10-50 万 → 第 3 年 50-200 万
XUNO 独有: AI 主动+语音+全人群+深度对话+私人定制（5 项无人同时具备）

#### #8 模型评估

- FashionSigLIP Fine-tune: Recall@10 提升 ≥15% vs 原版
- 推荐管道: CTR + Save Rate + Diversity + Coverage 四维评估
- 偏见审计: 5 Profile 同场景不同风格，80%+同性别编码 → 偏见
- A/B Testing: 规则 →+SigLIP→+SASRec 递增效果验证

#### #9 IP 战略

立即: 软著 + "寻裳""伊伊"商标注册
闭源: Fine-tune 权重、协调度模型、偏好模型、对话状态机
开源: 规则 JSON 文件（社区贡献）
可专利: 穿搭协调度评分方法、6 层漏斗实现
